# PageSift 1.1 measurements

Measured on one 16-thread machine with 15 GB of memory and a GTX 1070, with a local `cargo build --release` (no PGO).

Only the new build is measured. Earlier versions and other tools keep their recorded numbers, each with its date.

| Stage | Workload | Measured in this round |
|---|---|---|
| `v2speed` | A2 HTML and crawl replay, B1 PDF, B4 Office, 1 and 16 workers | Yes |
| `v2quality` | B1, B2, B3, B4, B5 frozen samples | Yes |
| `v2quality` | A1, A2, A4 frozen samples | No: numbers from [1.0](../1.0/README.md). The HTML, content and network crates did not change in 1.1 |
| `pdf`, `office` | olmOCR-bench, B4 | Yes |
| `extract`, `dates`, `markdown`, `rag`, `b3b5`, `crawl`, `wild`, `a3`, `browser`, `api`, `a2fast`, `b5ocr` | one dataset each | No: numbers from [1.0](../1.0/README.md), 2026-11-04. These paths did not change in 1.1 |
| xberg 1.3.9 | B1 and B4, default and layout mode | [`results/xberg-1.3.9/summary.json`](results/xberg-1.3.9/summary.json), 2026-11-04 |

Rows at 1 worker are the mean of two rounds on a warm page cache. The first round, right after the build, read every
file cold: peak memory counts the page cache of the worker's cgroup, so it came out up to 2.4 times higher. It is kept in
`metrics.measured.tsv`. Server-mode rows at 1 worker vary a lot between rounds. This run is not PGO; release binaries are.

## Run

```bash
RUN_ID=final SKIP_CHECK_EXAMPLES=1 benchmarks/history/1.1/regress.sh <bin dir> v2speed v2quality pdf office
python3 -I benchmarks/history/1.1/score/collect_xberg.py   # archives a recorded xberg run
python3 -I benchmarks/formats/smoke.py --pagesift <binary>  # new formats on real files
```

Tables and charts are generated by `score/publish.py` and `score/charts.py` from `results/final/new/scorecard.json`.
