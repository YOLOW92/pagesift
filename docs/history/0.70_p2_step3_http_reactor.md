# PageSift 0.70 P2 第三步：NUMA-Local HTTP/1.1 Reactor

> 日期：2026-10-25  
> 环境：Google Cloud `c4-highcpu-192`，Intel Xeon Platinum 8581C，192 vCPU / 96 物理核 / 2 Socket / 4 NUMA 节点  
> 当前判定：第三步已于 2026-10-25 由用户确认验收完成。本机自研 Reactor 核心与同机真实互联网 10,000 域名生产 Rustls 基线均已通过；Mio Reactor 原生 Rustls 接入仍是明确的后续优化，不把生产 Scraper 的结果冒充为该适配已经完成。

## 1. 实现边界

新增 `p2_http_reactor_runner`，在第二步 NUMA 所有权模型上替换 reqwest/hyper 热路径：

- 全部 PageSift 代码为 Safe Rust，源文件启用 `#![forbid(unsafe_code)]`；
- 使用 Mio 作为 Safe Rust epoll 封装，不使用 Tokio runtime、reqwest 或 hyper；
- 每个 Reactor 线程永久拥有固定连接槽，连接不跨线程、Socket、NUMA 节点转移；
- 固定任务采用确定性步进分配，没有全局任务计数器，也没有逐页 Future/Task/Spawn；
- 自研 HTTP/1.1 请求编码、响应头解析、Content-Length、chunked、close-delimited、keep-alive、限长、超时和幂等重试状态机；
- 支持多个 origin、多个解析地址和多个端口，连接按固定槽轮转分配；
- TLS 密码学没有自行实现。当前性能候选只接受 `http://`；正式 HTTPS 适配仍必须以 Rustls 为密码学边界。

第二步的关键规则保持不变：Reactor affinity 限制在所属 NUMA CPU 集，但不逐逻辑 CPU 精确硬绑。

## 2. 正确性验证

Release 测试共 8 项，全部通过：

- Content-Length 响应解析；
- chunked 响应及 trailer 解码；
- 不完整 chunk 等待后续数据；
- 同一连接连续三次 keep-alive 请求，确认仅建连一次、复用两次；
- 首次断连后重新连接、幂等重试并解析 chunked 响应；
- 两次超时后结束任务，正确记录一次失败、一次重试和两次超时；
- NUMA/线程/连接容量分配总数精确；
- 固定槽步进覆盖每个任务恰好一次。

双端口真实 socket 冒烟测试完成 100,000 页：`765,948.31 pages/s`，`failed=0`，1,536 次建连、98,464 次复用、0 重试、0 超时。

## 3. 公平 A/B

共同条件：

- 同一 `stream_origin`，12 个 `SO_REUSEPORT` listener；
- 每轮开始前重启源站，清空前一轮连接状态；
- 同一 5 个确定性页面、10,000,000 次请求；
- 1,536 个固定连接槽；
- 完整链路使用完全相同的 `pagesift_content::process`；
- CPU 只统计 Runner 自身 `/proc/self/stat` 的 `utime + stime`。

### 纯传输

| 实现 | 轮次 pages/s | 中位数 pages/s | Runner CPU 核 | failed |
|---|---|---:|---:|---:|
| reqwest/hyper 对照 | 721,138.81 | 721,138.81 | 45.16 | 0 |
| PageSift Reactor | 828,562.96 / 849,502.64 / 835,567.18 | **835,567.18** | **44.75** | 0 / 0 / 0 |

自研 Reactor 的纯传输中位数相对对照提升 `15.87%`；单位 Runner CPU 产出提升 `16.93%`。候选三轮均为 1,536 次建连、9,998,464 次连接复用、0 重试、0 超时。

### 完整端到端

| 实现 | 轮次 pages/s | 中位数 pages/s | Runner CPU 核 | failed |
|---|---|---:|---:|---:|
| 第二步 reqwest NUMA 固定槽对照 | 712,726.34 | 712,726.34 | 130.68 | 0 |
| PageSift Reactor | 913,012.49 / 920,359.25 / 902,892.46 | **913,012.49** | **134.31** | 0 / 0 / 0 |

完整链路中位数提升 `28.10%`，单位 Runner CPU 产出从 `5,453.84` 增至 `6,797.68 pages/core-s`，提升 `24.64%`。三轮结果跨度 `1.93%`，每轮均满足：

- `completed = valid = 10,000,000`；
- `failed = retries = timeouts = 0`；
- `bytes = 13,960,000,000`；
- `connects = 1,536`、`reused = 9,998,464`；
- 四个 NUMA 节点的任务差异只来自固定槽整数尾部。

纯传输低于完整链路的瞬时峰值不是解析“加速”网络，而是完整链路提供了自然背压，避免无解析请求洪峰把源站和回环队列推入更高争用区。正式结论使用各自同模式对照，不跨模式比较绝对值。

## 4. 验收状态

- [x] HTTP/1.1 keep-alive、Content-Length、chunked、断连、超时、限长和幂等重试状态机。
- [x] 热路径没有逐页 Spawn、完整响应框架二次聚合或全局连接池锁。
- [x] 本机多队列、多端口、纯传输和完整链路均为零失败，且明确高于旧 reqwest/hyper 路径。
- [x] NUMA 节点固定连接所有权与独立进度计数。
- [x] 真实公网验证：以同机 10,000 个不同 HTTPS 域名代替第二台收费实例，严格完成 10,000/10,000 任务。
- [x] 第三步 TLS 验收边界：生产 Rustls 路径已验证；Mio Reactor 原生 Rustls 接入转为后续优化，不阻塞第四步。

补充公网基线：生产 `Scraper/Rustls` 已对 10,000 个不同 HTTPS 域名完成一次严格封顶测试，5,687 成功、5,044 个有效正文、19.8466 秒完成；详见 [`0.70_p2_real_https_10k.md`](0.70_p2_real_https_10k.md)。该结果用于冻结真实目标与错误分布。

因此第三步按“自研明文 Reactor 核心 + 生产 Rustls 公网基线”的边界正式完成，可以进入第四步；原生 Mio/Rustls 适配继续作为独立性能优化项跟踪。
