# PageSift 0.70 P4 Step 4.2 · 标准基准基线（第 5～7 项）

> 仅运行 PageSift。第 1～4 项见 [0.70_p4_step4_2_baselines_1_4.md](0.70_p4_step4_2_baselines_1_4.md)。
> 本轮为**基线交付**，不做调优；对不堪用的项明确标注能力边界，不美化。

## 5. Google Security Crawl Maze 链接与动态发现

**环境**：`google/security-crawl-maze` `2a0dd0a7…`，本机以 Flask 起在 `127.0.0.1:8099`
（`allow_private_network=true`，robots 遵守，`--engine http`，`--limit 600 --depth 12 --entire-domain`）。

**口径**：从 `test-cases/` 提取所有应被发现的 `/test/**/*.found` 目标作为分母（60 个），
爬取后比对 `index.jsonl` 里的 URL 路径。

| 指标 | 值 |
| :--- | ---: |
| 应发现目标（`.found`） | 60 |
| 实际访问到的 `.found` | 6 |
| 其中命中目标清单 | **3** |
| 召回（3/60） | **0.0500** |
| 抓取页面数 | 136 |
| 错误 | 0 |

命中：`/test/html/body/a/href.found`、`/test/html/body/iframe/src.found`、
`/test/html/misc/url/root-relative-url.found`。

**诚实结论**：5% 的召回是本轮最弱的一项。根因不是"漏抓"，而是**定位不同**：
Crawl Maze 衡量的是"安全爬虫能否枚举出页面里引用的**资源型 URL**"（`img/dynsrc`、
`applet/archive`、`video/src` 等），而 PageSift 的 `crawl` 是**面向正文的可导航爬虫**，
只把可导航的 HTML 页记为抓取结果，非 HTML 资源不作为爬取目标入账。
`map` 子命令同样只输出 6 条（来自 sitemap），不适用于该测试床。
若要参与这项评分需要新增"资源 URL 枚举"模式，本轮不做。

## 6. robots 规范与站点完整度

**环境**：`google/robotstxt-spec-test` `552ade54…`，`CTC/correctness` 下 16 个 textproto。

**口径**：把 textproto 解析成 `{robotstxt, url, useragent, expected}` 共 **132 个判定用例**
（仅 `ALLOWED` / `DISALLOWED` 两类），直接调用 `pagesift_policy::Robots::parse(..).is_allowed(ua, path?query)`。

| 指标 | 值 |
| :--- | ---: |
| 用例数 | 132 |
| 通过 | **127** |
| 通过率 | **0.9621** |

按文件：

| 文件 | 通过 / 总数 |
| :--- | ---: |
| matching-path-values-1 | 29 / 29 |
| matching-path-values-2 | 24 / 24 |
| most-specific-match | 14 / 14 |
| user-agent-name | 14 / 14 |
| groups | 10 / 10 |
| special-characters | 10 / 10 |
| directives-case-insensitivity | 6 / 6 |
| order-of-precedence | 5 / 5 |
| global-rules | 4 / 4 |
| **non-ascii-paths** | **4 / 7** |
| index-page | 3 / 4 |
| accepted-mistakes | 2 / 3 |
| uri-case-sensitivity | 2 / 2 |

**5 个失败**：
- `non-ascii-paths` ×3：`/foo/bar/ツ` 等非 ASCII 路径被误判为 ALLOWED（百分号编码/字节归一化差异）。
- `index-page` ×1：`http://foo.com/allowed-slash/` 期望 ALLOWED，实际 DISALLOWED。
- `accepted-mistakes` ×1：该文件本身就是"常见实现错误"集合，此例期望 DISALLOWED、实际 ALLOWED。

96.21% 是可用的基线；`non-ascii-paths` 一次占 3 个失败，是最集中的缺陷方向。
