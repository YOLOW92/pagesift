# PageSift 0.70 P2 Step 4.2：统一流水线闭环与按主机自适应连接

日期：2026-10-25  
执行环境：Google Cloud `c4-highcpu-192`，192 vCPU Intel Xeon Platinum 8581C，双 Socket、4 NUMA  
实现边界：Safe Rust；生产直连客户端与 P2 Mio Reactor 测试路径

## 结论

Step 4.2 已把固定的“所有 host 使用同一连接数”替换为按 origin 隔离的运行期闭环，并把 Step 4.1 的 `48 Reactor + 144 内容线程` 从启动拓扑结果升级为可在线改变工作份额的统一流水线控制器。

在三轮固定/自适应快慢 host 对照中，容量为 4 的慢 host：

- 固定 32 路连接的 503 中位数为 `9,627/10,000`，过载率 `96.27%`；
- 自适应的 503 中位数为 `317/10,000`，过载率 `3.17%`，下降 `96.71%`；
- 慢 host 峰值在途从 `32` 限制到 `5`，终态热水位为 `5/4/5`，围绕真实容量 4 运行；
- 慢 host 成功吞吐中位数从约 `188.3 req/s` 提升到约 `647.2 req/s`，为 `3.44x`；
- 快 host 不跟随慢 host 回退，三轮终态热水位为 `29/28/28`，且始终 0 失败；
- 三轮均无传输失败或取消，慢 host 只建立 5 条连接并复用 9,995 次，证明冷探测连接消除了反复重连。

固定模式约 10k 的“总 QPS”不代表有效吞吐，因为其中绝大部分慢 host 请求以 503 快速结束。本报告以成功请求、过载率和 host 独立水位作为连接控制的主要指标。

## 实现

### 1. 按 origin 隔离的连接控制器

生产 `pagesift-net` 直连路径为每个 `scheme + host + port` 建立独立状态：

- 初始热连接水位为 2，默认安全上限为 32；
- 连接许可从请求开始一直持有到响应体 EOF，覆盖 DNS、TCP、TLS、TTFB 和 body 生命周期；
- 许可的 `Drop` 路径会释放活跃计数并记录取消，避免超时或任务取消泄漏容量；
- 成功且饱和的 16 请求窗口逐级扩张；错误率或可测的服务时间退化触发回退；
- 429/503 立即只让对应 host 退一级，同一冷却窗口内的并发过载响应不叠加惩罚；
- HTTP/1 池保留“当前热水位 + 1”条空闲连接作为冷探测储备，重新挑战容量时无需重新建连；
- 每个 host 输出目标水位、活跃数、成功/失败/过载/取消、建连/复用和服务时间 EWMA。

控制器没有后台扫描器，也不遍历并发网格；只有真实请求完成事件才能改变水位。

### 2. Step 4.1 的统一流水线闭环

线程仍在启动时按 CPU/NUMA 拓扑创建并固定归属，运行时不重建线程、不迁移 Socket。统一控制器改变的是：

- 每个 NUMA 节点允许消费本地内容队列的活跃 Worker 配额；
- Reactor 原地解析的确定性份额；
- Reactor 等效工作预算与内容工作预算。

每次最多移动一个 NUMA 平衡量子，观察吞吐、PageSift 自身 CPU、队列深度、背压率和失败率；新配额需要稳定窗口，退化则回到已记录最佳点并锁定，之后只低频复探。

10M VPS 功能烟测从拓扑初值 `48/144` 自动移动到 `64/128` 和 `80/112`，Reactor 原地解析份额从 `0%` 增到 `12%`、`23%`；完成 `10,000,000/10,000,000`，失败 0。

修正“锁定后连续复探”后又执行 50M 长窗口验证：首次有限探索经过 `64/128`、`80/112`、`96/96`、`112/80` 后回退并锁定 `80/112`；此后两次低频挑战分别只测试相邻的 `64/128` 和 `96/96`，均立即返回 `80/112 Locked`，没有继续扫描。最终吞吐 `929,472 pages/s`、失败 0，Runner 平均使用 `122.97` 个逻辑核。

## 固定/自适应三轮结果

每轮向快速 host 和容量受限 host 各发送 10,000 个请求。慢 host 服务时间设为 5 ms，并在同时活跃请求超过 4 时返回 503。固定模式每 host 32 路；自适应模式只给出相同的 32 路安全上限，不提供甜点值。

## 边界

- 当前按 host 控制已进入生产直连 Hyper/Rustls 路径；配置出口代理时仍由 reqwest 管理代理连接，暂不暴露目标 origin 的独立池状态。
- HTTP/2 复用共享一条传输连接，但相同 host 控制器仍限制请求生命周期水位；后续 TLS/HTTP2 Reactor 原生化属于 4.4 的分阶段容量工作。
- 4.2 解决的是连接生命周期和 host 隔离，不代替 4.3 的本地任务入口、批量领取和饥饿 stealing。
