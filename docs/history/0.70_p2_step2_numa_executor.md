# PageSift 0.70 P2 第二步：NUMA-Local 固定槽执行器

> 日期：2026-10-25  
> 环境：Google Cloud `c4-highcpu-192`，Intel Xeon Platinum 8581C，192 vCPU / 96 物理核 / 2 Socket / 4 NUMA 节点  
> 结论：第二步通过。相同 HTTP 与内容处理组件下，正式候选中位吞吐从 `656,052.09` 提升到 `712,643.07 pages/s`，提升 `8.63%`，全部请求成功。

## 1. 本步只替换什么

为了隔离执行器收益，A/B 两侧均使用：

- 同一 `stream_origin`，12 个 `SO_REUSEPORT` listener；
- 同一组 5 个确定性 HTML 页面，单轮 10,000,000 页；
- 同一 `reqwest` 客户端和 `pagesift_content::process`；
- 1,536 个长驻请求槽、96 个连接池；
- Runner 自身 `/proc/self/stat` 的 `utime + stime` 作为唯一正式 CPU 指标。

旧对照是一个全局 Tokio runtime 上的长驻槽；新候选由 `p2_numa_slot_runner` 实现：

- 每个 NUMA 节点一个独立 runtime、Worker 组、连接池组和计数器；
- 启动时只创建固定数量的槽任务，不逐页 `tokio::spawn`；
- 任务 ID 采用确定性跨槽步进，单元测试验证恰好覆盖一次；
- 每个节点固定拥有 384 个槽和 24 个连接池，禁止跨 NUMA 工作窃取；
- Worker 的 affinity 是“NUMA 节点 CPU 集”，由 Linux 在节点内调度，而不是逐逻辑 CPU 硬绑定。

当前仍复用 Tokio Reactor 和 reqwest；它们将在第三步替换。本步自研的是 NUMA 所有权、固定槽生命周期和任务分配层。

第一轮是有效的高值，但没有把它当成结论；后续连续三轮稳定在 `712,207.62–712,736.49 pages/s`，最大差仅 `0.074%`。四轮中位数相对旧对照提升 `8.63%`。单位 Runner CPU 的产出从 `5,015.84` 提升到 `5,470.50 pages/core-s`，提升 `9.07%`，说明收益来自调度效率而非简单消耗更多 CPU。

所有正式轮次均满足：

- `completed = valid = 10,000,000`；
- `failed = 0`；
- 响应字节数均为 `13,960,000,000`；
- 四个 NUMA 节点分别完成 `2,500,224 / 2,500,096 / 2,499,840 / 2,499,840` 页，差异仅来自 1,536 个槽的整数步进尾部，没有任务集中、丢失或重复。

## 3. 被证伪的绑核方式

第二步同时留下了三个重要反例：

| 变体 | 吞吐 pages/s | Runner CPU 核 | 相对全局对照 | 结论 |
|---|---:|---:|---:|---|
| 192 Worker，逐逻辑 CPU 精确绑核（三轮中位） | 433,558.41 | 159.60 | -33.91% | 强迫 SMT 兄弟同时繁忙，节点内无法避让 |
| 上述方案加协调线程首次触碰本地化 | 433,616.36 | 158.63 | -33.90% | 远端首次分配不是主因 |
| 96 物理核 Worker，逐核精确绑核 | 356,519.83 | 83.61 | -45.66% | Worker 不足以同时推进解析和网络槽 |
| 192 Worker，限制在 NUMA CPU 集但节点内可迁移 | 712,643.07 | 130.27 | +8.63% | 通过 |

Intel 双路 SMT 机器上的正确约束不是“每线程永远固定在一个逻辑 CPU”，而是“不得跨 NUMA，节点内交给内核选择物理核或 SMT 兄弟”。这也解释了为什么 CPU 使用更多的精确绑核版本反而更慢：其单位 CPU 有效产出严重下降。

## 4. 验收判定

- [x] 固定槽覆盖单元测试通过，0 丢任务、0 重复任务。
- [x] A/B 页面集、HTTP、内容处理、并发和连接池完全一致。
- [x] 四节点独立进度与计数齐全，正式候选 `failed = 0`。
- [x] 正式候选吞吐明确高于全局 Tokio 对照，中位提升 `8.63%`。
- [x] Runner 进程 CPU 时间来自 `/proc/self/stat`，没有使用系统或源站 CPU 代替。

因此第二步通过，可以在用户确认后进入第三步：保持这套 NUMA 所有权和节点内 affinity 规则，替换 reqwest/hyper 通用请求生命周期为自研分片 HTTP Reactor 与连接池。第三步不得把本次验证出的逐逻辑 CPU 精确绑核重新引入正式路径。
