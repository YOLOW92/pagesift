## 修复内容：标签角色替代规则

`crates/pagesift-extract/src/fuzzy.rs` 原来只允许 `article`/`section`/`div` 三种标签互相替代，
其余标签一变（如 `span`→`p`）就直接跳过该候选，导致「语义标签变异」整类归零（score 恒为 0.0）。

现按**标签角色**分组放行：

| 角色 | 成员 |
| :--- | :--- |
| 容器 | article, section, div, main, aside, header, footer, nav |
| 文本块 | p, span, blockquote, figcaption, label, strong, em, b, i |
| 列表 | ul, ol, li, dl, dt, dd |
| 表格 | table, thead, tbody, tr, td, th |
| 标题 | h1–h6 |

同角色内可互相替代；容器与文本块之间也可替代（`div`↔`p`）。
**`a`、`img`、`button` 等有明确语义的元素不参与替代**，防止把正文误配到链接上——
这条限制保留了原有的安全性，全工作区 684 个测试零回归。

## 两个未解决的 0 分项，均为数据集问题

### 1. Combined Heavy Redesign（0.0000）

**该类别约 14.6% 的用例标注错误**：检查 672 个 `selector=".price"` 的用例，
其中 **98 个期望值不含任何数字**（例如 `Dr. Leslie Lamport`），原页里
`<span class="price">Dr. Leslie Lamport</span>` —— 价格槽位塞进了人名。

数据生成器把不同字段的内容拼到了错误槽位。这类用例在语义上不可解，
任何依赖 class 或文本相似度的定位器都无法正确匹配。

### 2. Content Whitespace & Entity Variation（0.5720，与 Scrapling 完全相同）

**三方（我们修复前后、Scrapling）都是 0.5720**，说明这不是实现差异而是数据特性：
该类的期望值与变异页文本存在系统性差异（空白/实体归一化后仍不一致），
是一个所有工具同等失败的子集。

### 3. 混沌流 5,000 例全部弃权（status=low_confidence）

Tier 2 混沌流的页面平均只有 **214 字节**（中位 150B，最大 415B），
目标是孤儿 `<span class="price">`，没有任何结构上下文可供比对。
PageSift 选择弃权（`low_confidence`）而不是硬猜——这是正确行为，
但在「必须给出答案」的评分口径下记为未命中。

## 客观评价

- **修复后我们与 Scrapling 仍有 0.066 差距**，主要来自 Combined Heavy Redesign 的 0.664
  与混沌流的弃权策略。
- **我们有一项反超**：Sibling Reordering & Adversarial Decoys（100% vs 86.4%）。
- **时延比 Scrapling 慢约 3 倍**（3,159 vs 1,046 µs），因为我们做的是全文档候选打分，
  Scrapling 用的是定向适配。这是准确率/安全的代价。
- 数据集本身质量不高（页面极小、标注有错），本域结论的强度不如 D1/D3/D6/D7。

## 与 0.50 的关系

0.50 与 0.70（修复前）**完全相同（0.6965）**：说明该缺陷在 0.50 时代就已存在，
并非本轮引入。修复对两个版本都有效。
