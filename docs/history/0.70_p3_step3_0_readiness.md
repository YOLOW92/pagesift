## 正式入口

- Runner：`bench/p0/target/release/p2_http_reactor_runner`
- 源站：`bench/p0/target/release/stream_origin`
- 编排与门禁：`bench/p3/run_100m_gate.sh`
- 路径：自研 Safe Rust Mio HTTP/1.1 Reactor、NUMA 本地完成队列、融合内容解析、拓扑自适应 SO_REUSEPORT 源站。

`--formal` 模式强制完整解析和分层流水线，拒绝手工 `--connections`、`--reactors`、关闭自适应分发、改变五类固定内容或改变 `1/10,000` 抽检率。正式任务只传总任务数，连接初值和安全上限来自硬件/cgroup 拓扑。

## 新的自适应连接入口

旧 Runner 虽然能自动调节 Reactor/内容工作份额和 NUMA 分发，但仍会默认建立固定 `1,536` 个连接。P3 入口已将它替换为：

1. 启动时由拓扑生成连接初值与资源安全上限；
2. 所有连接槽预分布到 NUMA 节点，但只有控制器批准的槽会建连；
3. 连接槽可在请求边界动态启停，缩容不会中断在途响应；
4. 页面任务改用全局原子序号领取，扩缩容不会留下静态 stride 空洞，也不会重复领取；
5. 容量控制器先收敛，随后流水线控制器和 NUMA 分发控制器依次取得探索权，避免多控制器同时换参；
6. 内容队列在 Reactor 结束后必须排空，取消或停机不能把排队解析伪装成完成；
7. 每 10,000 个任务保存一个确定性的正文 BLAKE3、任务号和字节数到正式 JSON，共 0.01%。

容量控制器进行有限的方向性探索、退化回退、锁定和低频相邻复探，不执行网格扫描。正式门禁脚本拒绝覆盖已有结果，并在成功后校验任务守恒、节点守恒、抽检唯一性、进程 CPU、内存和控制轨迹。
