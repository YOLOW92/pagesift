# 0.70 亿级吞吐验证（192 核 200M · 本机 16 核 100M）

**目的**：用整亿级任务量确认 0.70 相对 0.61 的吞吐与每页 CPU 成本。

**口径**：`stream_origin` 本地合成源站 + `p2_http_reactor_runner`，
`--formal --mode full --split-pipeline`，源站与受测进程同机。
192 核机器为 `c4-highcpu-192`（Intel Xeon Platinum 8581C，377 GiB，4 NUMA）；
本机为单路 16 逻辑核 / 15 GB。

## 1. 最终结果

| 运行 | 任务数 | 墙钟 | 持续吞吐 | 进程 CPU | 平均占用核 | **每核吞吐** | **每页 CPU** | 峰值 RSS |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **0.61 基线**（192 核） | 100,000,000 | 234.2 s | 427,033 p/s | — | 84.1 / 192（43.8%） | 5,078 | 196.9 µs | — |
| **0.70**（192 核） | 200,000,000 | 211.057 s | **947,611 p/s** | 31,659.1 s | 150.0 / 192（78.1%） | **6,317** | **158.3 µs** | 888.1 MiB |
| **0.70**（本机 16 核） | 100,000,000 | 1,686.088 s | 59,309 p/s | 16,621.8 s | 9.86 / 16（61.6%） | **6,015** | **166.2 µs** | 124.1 MiB |

| 相对 0.61 | 192 核 | 本机 16 核 |
| :--- | ---: | ---: |
| 绝对吞吐 | **2.22×** | — |
| 每核吞吐 | **+24.4%** | **+18.5%** |
| 每页 CPU | **−19.6%** | **−15.6%** |

**结论：0.70 比 0.61 更快、每核更强、每页更省 CPU。**
192 核上从 42.7 万页/秒提升到 94.8 万页/秒，同时每页 CPU 从 196.9 µs 降到 158.3 µs。

两次运行均为 `completed = valid = total_tasks`、`failed = 0`、零超时零重试，
源站请求数与任务数精确相等（100,000,000 / 200,000,000），抽样 10,000 / 20,000 条（1/10,000）。

## 2. 每核效率与平台无关

本机 16 核每核 6,015 p/s/核，192 核每核 6,317 p/s/核，相差 4.8%。
即使只有 16 核、源站还占着同一批核心，每核产出仍与 192 核一致——
说明 192 核上的 94.8 万页/秒是新数据面的线性扩展，不是某个平台的偶然结果。

## 3. CPU 花在哪

每页多做一次正文容器定位（容器规律 + Readability 打分两候选择优），
换来 WebMainBench 全量 ROUGE-5 F1 `0.5860 → 0.6414`（+0.055），
从「低于全部公开基线」提升到与 Trafilatura 持平、超过 Resiliparse。

即便加上这部分，0.70 的每页 CPU 仍比 0.61 低 19.6%：
数据面省下的 CPU 多于正文定位花掉的。

吞吐敏感、不需要正文收窄的场景可以设 `PAGESIFT_NO_FORCE_ARTICLE=1` 回到整页输出。

## 4. 过程中修掉的一处实现问题

首版 200M 在 `process_dom` 里**逐页**调用 `std::env::var_os` 读取开关，
每页一次全局锁 + environ 扫描。改为 `OnceLock` 进程内只读一次后，
吞吐回升 7.7%（879,682 → 947,611 p/s）。这与正文定位无关，纯属开关写法问题。

## 5. 复现

```bash
# 用当前代码重编 runner 与源站（benchmarks/scale/p0 依赖 pagesift-content）
cd benchmarks/scale/p0 && cargo build --release --bin p2_http_reactor_runner --bin stream_origin

# 192 核 200M
bash benchmarks/scale/p3/run_200m_check.sh <tag>

# 本机 100M
bash benchmarks/scale/scripts/local_100m.sh
```

产物：`benchmarks/scale/results/0.70_200m_cached.{json,log,meta.json}`、
`benchmarks/scale/results/0.70_local_100m.{json,log,meta.json}`。

## 6. 备注

- `capacity_adjustments` 在 200M 为 5 次、本机 100M 为 7 次，自适应容量控制器确实在动作。
- 本机峰值 RSS 124 MiB、192 核 888 MiB，差异来自连接数与 NUMA lane 数量，
  两侧都远低于 `2 GiB` 门禁。
- 本轮为本地合成源站，不涉及网络，不代表联网吞吐。
