# 0.70 十域对决 · D6 编码识别（chardet-test-data 全量）

## 口径

| 项 | 值 |
| :--- | :--- |
| 数据 | `chardet-test-data` **3,128 个文件 / 89 种编码 / 49 种语言** |
| 指标 | 复用 0.50 `eval_d6_050.py` 的 `canon()` + `is_compat()` 判定（含编码族等价规则） |
| 内存 | 每个参赛者 10 GiB 上限 |
| 并发 | PageSift 16 线程；Python 竞品统一 16 分片并行 |

## 结果

| 参赛者 | 准确率 | 文件数 | 墙钟 | 文件/秒 | 峰值内存 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| **PageSift 0.70** | **0.7602** | 3,128 | 0.28 s | **11,239** | **39 MiB** |
| PageSift 0.50 | 0.7602 | 3,128 | 0.17 s | 18,845 | 41 MiB |
| chardet | 0.7113 | 3,128 | 0.46 s | 6,800 | — |
| cchardet | 0.5310 | 3,128 | 0.20 s | 15,640 | — |
| charset-normalizer | 0.5301 | 3,128 | 0.22 s | 14,218 | — |

**PageSift 0.70 准确率全场第一**，比 chardet 高 4.9 个百分点，比 cchardet / charset-normalizer 高 23 个百分点。

## 按编码族（0.70 与 0.50 完全一致）

| 编码族 | 准确率 | 文件数 |
| :--- | ---: | ---: |
| Unicode（UTF-8/16/32/7） | **0.9974** | 1,553 |
| CJK（中日韩） | 0.8087 | 230 |
| Cyrillic（俄/乌/斯拉夫） | 0.5806 | 279 |
| Western & Latin（Latin-1/15, CP1252/1250） | 0.5000 | 606 |
| Legacy & Others（希腊/希伯来/阿拉伯/EBCDIC/DOS） | **0.3870** | 460 |

Unicode 族几乎满分（0.9974），这是主力场景。失分集中在 **EBCDIC/DOS 老编码族（0.3870）**
与 Western & Latin（0.5000）——后者大量样本是"纯 ASCII 内容但声明为 cp1252/latin-1"，
判定为 ascii 时按 `is_compat` 规则算对，但部分变体不在等价表里。

## 与 0.50 的关系

**0.70 与 0.50 准确率完全相同（0.7602）**：本轮没有改编码识别逻辑，符合预期。

速度上 0.70 慢一些（11,239 vs 18,845 文件/秒），原因是 0.70 多了 UTF-7/EBCDIC/CP437 框线
等启发式预检。这个代价换来的是 0.70 在 Legacy 族上的判定能力——不过本次两版分数相同，
说明这些预检在 chardet 数据集上没有额外命中，属于**未被该数据集验证的增强**。

## 备注

- 0.50 报告写的是 74.4% 准确率，本次同机实测 0.7602（76.02%），差异来自数据集版本与主机不同，
  以本次为准。
- 三个 Python 竞品在同一容器、同一批 3,128 文件上跑，无 OOM。
