# 0.88 PDF：按页质量分与复核、失败分桶、解析时限

日期：2026-11-02。基线：冻结的 0.81.5 二进制；新版：本次改动后 `--profile release-fast` 编出的二进制（哈希见 `benchmarks/history/0.88/results/20261102-pdf/binaries.sha256`）。
评测：`benchmarks/mix/run_batch.py b2/b3/b5:pagesift-081-file` + `score_quality.py`（0.81 的脚本和语料：B2 71 份、B3 100 份、B5 134 页），配对 bootstrap 脚本 `results/20261102-pdf/scripts/paired.py`（δ = 0.05，重抽样次数加倍到端点蒙特卡洛误差 < 统计误差的 1/10）。

## 做了什么

1. **按页质量分**（`crates/pagesift-pdf/src/quality.rs`）：解释时顺带数乱码字符（U+FFFD、私用区、控制字符）、字体映射缺失（字体给不出 Unicode 被丢的字形）、阅读顺序跳变（内容流里换行时往回跳）。`PdfPage::quality` 对外公开，含 `score()`。
2. **低分页复核**：门槛用 δ 规则——缺字数的 Wilson 下界 > δ 才判为低分页（不写死比例）；没有字但有被略过的按钮表单域也复核。只重做这一页，换路径：字体不信 ToUnicode 里的乱码项，改用字体自身编码、TrueType cmap、字形名；按钮标题（外观流或 /MK /CA）也收。好字多的那次胜出。
   - 取舍：阅读顺序跳变只记分、不触发重做。理由：版面重组本来就不按内容流排字；三个评测集都没有阅读顺序标注，换排法是否更好无从判定，贸然换会有不可测的回退风险。
3. **失败分桶**（B3，0.81.5）：

   | 桶 | 份数 | 处理 |
   |---|---|---|
   | 加密且需要口令（pdf.js 清单里给了口令：Hello、test、pässwört、ELXRTQWS、abc、æøå、SASLprep；print_protection 连 MuPDF 也要口令） | 8 | 正确行为，不改 |
   | 截断/模糊测试生成、文件里没有页面对象（REDHAT-1531897-0、poppler-85140-0） | 2 | MuPDF 也打不开，不改 |
   | 页面唯一的字在按钮上（secHandler、js-authors、resetform_parent） | 3 | 复核路径收按钮标题，**已修** |
   | 只有图、没有文字层（bitmap-*、issue5481/5567/7229 等） | 5 | 标出扫描页（见 0.88_images.md），不做 OCR |
   | 只有矢量图形、表单空值、注释无字等（MuPDF、poppler 也是空） | 18 | 没有可提取的字 |
   | 坏 ToUnicode 且字体无 cmap、post 表无字形名（B1 的 tables-0486cc…） | — | 复核触发但两条路都没有好字，保持原样（不是 B3 项） |

4. **解析时限**（`crates/pagesift-pdf/src/timeout.rs`）：`ln t = β₀ + β₁ ln b` 最小二乘 + 残差上尾的超阈值法（阈值 q(1−δ)，超出部分按指数尾，均值 m），时限 `exp(ŷ + s·(u + m·ln n))`，`ε = δ/n` 做 Bonferroni；超出见过的最大文件按线性外推。先验包是 0.81.5 在 B1/B2/B3/B5（1 路、16 路）1,859 次成功解析的计时。每个线程一份本地统计、解析成功就更新（不加锁）。用户时限是硬上限。
   - 留一集交叉验证：7 个集各自留出、其余拟合，**错杀 0 份**，最小余量 e^1.9 ≈ 6.6 倍。
   - 时限示例（无用户上限）：1 KB ≈ 1.1 s，1 MB ≈ 3.5 s，10 MB ≈ 5.1 s，150 MB ≈ 55 s（线性外推）。
   - 取舍：没有用 `pagesift_stat::regress`（它没有从充分统计量直接构造的接口），一元回归闭式解写在本文件里。

## 结果（配对 bootstrap，Δ = 新 − 旧；越高越好）

| 集 | 指标 | 旧 | 新 | Δ | 95% 区间 | 判定 |
|---|---|---|---|---|---|---|
| B2 71 份 | 文字完整度（官方口径） | 0.93675 | 0.93676 | +0.000013 | [0, 0.000035] | 提升（见下） |
| B2 | 文字完整度，去掉扫描页说明行 | — | — | +0.000004 | [0, 0.000012] | 不降 |
| B2 | 完成率 | 0.986 | 1.000 | +0.014 | [0, 0.042] | 不降 |
| B3 100 份 | 完成率（官方口径：输出非空） | 0.64 | 0.72 | +0.08 | [0.03, 0.14] | **提升**（单侧下界 0.04） |
| B3 | 有文字的完成率（去掉扫描说明和图片引用） | 0.64 | 0.67 | +0.03 | [0.00, 0.07] | **提升**（单侧下界 0.01） |
| B5 134 页 | 完成率（官方口径） | 0.112 | 1.000 | +0.888 | [0.828, 0.940] | 口径假象 |
| B5 | 有文字的完成率 | 0.112 | 0.112 | 0 | [0, 0] | 不变 |
| B5 | olmOCR 总分 / 去掉 baseline | 0.037 / 0.000 | 0.378 / 0.067 | | | 口径假象 |

如实说明：
- B2 的“提升”来自两份文件的扫描页说明行里的英文词（page、image…）计入词覆盖率；去掉说明行后只有 1 份（1603.00122，一页复核替换）有 +0.0003 的真实变化，结论是**不降**。B2 71 份里 4 页触发复核、3 页被替换。
- B5 不做 OCR：完成率和 olmOCR 分的上升全部是扫描页说明行让输出非空、让“不该出现的文字”类测试和 baseline 类测试通过，不是识别出了文字。有文字的完成率不变（0.112）。
- 与 pdf_oxide 的差距（B2 文字完整度 0.937 对 0.962）不是乱码页，而是口径：把输出里的 LaTeX 数学还原成 Unicode 后同一批输出就是 0.957（`scripts/b2gap.py`）；其余主要是去掉的页眉页脚和页码。数学写法没有改，因为它会影响 B1 的数学测试。
- 没跑 B1 和测速，只跑了三个 PDF 集。复核只多解释被判为低分页的那几页；扫描页多一次图像数据的 SHA-256。

## 接口

- `pagesift_pdf::Options { timeout, adaptive_timeout: true, .. }`：`timeout` 现在是**用户硬上限**，默认 `None`；实际时限 = min(上限, 回归时限)。引擎（`crates/pagesift-engine/src/engine/pdf.rs`）把请求剩余的截止时间作为上限传入，请求没有截止时间时为 `None`。
- `pagesift_pdf::parse_timeout(bytes, cap) -> Duration`、`observe_parse(bytes, elapsed)`：按文件字节数给出时限、记录一次成功解析的耗时，公开可用。
- `PdfPage::quality: PageQuality`（chars、garbled、unmapped、breaks、jumps、rechecked、replaced、`score()`）。
