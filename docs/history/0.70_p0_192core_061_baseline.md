## 3. 深层瓶颈剖析：56% 算力闲置的物理根因

通过现场遥测数据与系统架构分析，锁定了 0.61 在超多核机器上的三大瓶颈：

1. **经验公式导致的“分片欠饱和”**：
   - 0.60 遗留公式 `S = ceil(N_cpu / 8)`，在 192 核上仅计算出 **24 个分片（Shards）**。
   - 192 个硬件执行单元仅由 24 个单线程调度分片驱动，每个分片负责 8 个核心，派发速度与并发深度无法喂饱整个 CPU，导致 CPU 均载死死卡在 43.8%。

2. **忽略了 4 个物理 NUMA 节点的内存惩罚**：
   - 192 核实例开启了 SNC-2，划分为 4 个物理 NUMA 节点（每个节点 48 个 vCPU）。
   - 0.61 的分片未绑定 NUMA Node，工作线程在 4 个 NUMA 节点之间随机漂移调度，产生频繁的跨 Socket / 跨 NUMA 远端内存借道开销。

3. **单回环端口（Loopback Port）的内核软中断瓶颈**：
   - 1 亿个 HTTP 请求全量打向单个监听端口（`127.0.0.1:19800`）。
   - 在 Linux 内核网络协议栈中，单端口回环套接字在 40~45 万 QPS 时，单核内核软中断（ksoftirqd）已逼近物理饱和，成为客户端与服务端两头的刚性漏斗。

## 4. 0.70 突破指引

通过在 0.70 引入 **NUMA-Local 本地化分片拓扑**、**多套接字/SO_REUSEPORT 分发**、以及**饱和分片提升（48~96 分片）**，预计在 192 核机器上将 CPU 激活至 85%+，持续吞吐有望从 42.7 万 QPS 突破至 **800,000 ~ 1,000,000 pages/sec**！
