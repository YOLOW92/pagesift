# 0.91 — Fixes from the 0.90.0 code review

The review (2026-11-03, static reading of commit `1ef27b1`) listed 14 findings, F-01 … F-14. This page records
what 0.91 changed for each, the test that covers it, and what was not changed. All tests are local; none of them
touches a real website.

"Fails on 0.90" means the test was run against the 0.90 code (or the 0.90 rule restored in place) and failed.
"New interface" means the test uses something 0.90 does not have, so it cannot run there; the 0.90 behaviour is
then shown by reading the code.

## Measured on this machine

See the 0.91.0 release notes: speed and byte-identical output (`results/speed-20261103-072644`,
`results/compare-20261103-072825`), render decisions with Chromium (`results/render-20261103`), and the
built-in quality score against absolute labels (`results/quality-absolute-wmb.json`).

## Left as is, with the reason

- The quality score is not refitted with an absolute label: 0.91 uses it only to compare results, and a refit
  needs the four 0.83 sets, three of which are not on this machine. Its distance from an absolute probability is
  measured (release notes, *Render decisions*).
- The Jina SSE stream does not emit blocks while the page is parsed: the extractor decides what is main content
  after scoring the whole DOM.
- F-10 (single internal data model, per-output receipts) and F-14 (cluster throughput) are documentation
  findings; 0.91 states what exists and measures nothing new for the cluster.

## Environment and test run

4-CPU cloud VM, Linux 6.18, Rust 1.97. `RUSTFLAGS="-D warnings" cargo test --workspace --locked --profile quick
--exclude pagesift-cdp --no-fail-fast` (the command of `scripts/ci.sh`) as root, plus the tests that need a
browser run again as an unprivileged user (pagesift does not start Chrome as root);
`cargo clippy` with the same flags, `scripts/check_literals.sh`, `check_wall_clock.py`, `check_release.py`.
