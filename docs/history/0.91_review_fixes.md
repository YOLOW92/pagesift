# 0.91 — Fixes from the 0.90.0 code review

The review (2026-11-03, static reading of commit `1ef27b1`) listed 14 findings, F-01 … F-14. This page records
what 0.91 changed for each, the test that covers it, and what was not changed. All tests are local; none of them
touches a real website.

"Fails on 0.90" means the test was run against the 0.90 code (or the 0.90 rule restored in place) and failed.
"New interface" means the test uses something 0.90 does not have, so it cannot run there; the 0.90 behaviour is
then shown by reading the code.

## Not done in 0.91

- No external single-writer authority (lease service, shared-storage fence) for the standby. A partition between
  primary and standby with the primary still serving workers was not tested.
- The quality score was not refitted with an absolute label, and it was not calibrated separately for browser,
  PDF, Office or data-island results.
- Render rates and extraction quality on the comparison sets were not re-measured after the render-decision
  change.
- No incremental extraction for the Jina SSE stream; no per-output delivery receipts.
- Attachments are not replicated to the standby; there is no disk limit for stored attachments other than their
  24 h expiry.
- A local store write error (as opposed to a replication error) is not injected by a test; it goes through the
  same branch of `JobSink` minus counting the page.

## Environment and test run

4-CPU cloud VM, Linux 6.18, Rust 1.97. `RUSTFLAGS="-D warnings" cargo test --workspace --locked --profile quick
--exclude pagesift-cdp --no-fail-fast` (the command of `scripts/ci.sh`), plus `cargo clippy` with the same flags
(clean) and `scripts/check_literals.sh`, `check_wall_clock.py`, `check_release.py` (all pass).

Failures in that run, each checked against 0.90.0 built from `1ef27b1` in the same environment:

- The same 13 tests fail on 0.90.0 and 0.91.0 and are caused by the environment: 10 in `pagesift-net`
  (`tests/fetch.rs`, `host_latency.rs`, `host_slots.rs`, `sessions.rs`; requests go through the VM's HTTPS proxy)
  and 3 in `crates/pagesift/tests/it` (`scrape::an_engine_that_cannot_launch_is_skipped_after_the_first_failure`
  and `cluster::priors_audit_and_metrics_go_through_the_gateway` need a browser, which refuses to run as root;
  `scrape::dns_failures_and_unknown_egress_are_distinct_errors` gets an answer from the proxy for an `.invalid`
  host).
- `pagesift-cluster` `tests/snapshot.rs` `standby_follows_snapshots_and_resyncs` fails now and then under load.
  Six copies in parallel, 15 runs each, 20 s timeout: 13 of 90 runs fail or hang on 0.90.0, 7 of 90 on 0.91.0;
  alone it passed 40 of 40 on 0.91.0. Not investigated further in 0.91.
