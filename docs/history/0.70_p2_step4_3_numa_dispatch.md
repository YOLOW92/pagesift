# PageSift 0.70 P2 Step 4.3：NUMA 本地分片入口与自适应 Work Stealing

日期：2026-10-25  
执行环境：Google Cloud `c4-highcpu-192`，192 vCPU Intel Xeon Platinum 8581C，双 Socket、4 NUMA  
实现边界：Safe Rust；P2 Mio Reactor 完整解析链路；CPU 仅统计 Runner 自身 `/proc/self/stat` 的 `utime + stime`

## 结论

Step 4.3 已完成。旧的“每个 Reactor 拥有一个封闭内容队列”被替换为每 NUMA 节点内部的分片队列组：Worker 首先消费自己的本地 lane，本 lane 空闲时帮助同节点其他 lane，只有连续本地饥饿达到运行期阈值后才跨 NUMA stealing。Socket、连接状态和响应缓冲回收目标仍归原 Reactor 所有。

控制器同时调节本地批量、连续空轮询阈值和跨节点批量；每次只挑战一个相邻档，无明确收益立即恢复最佳点并锁定，锁定后仅低频复探。统一闭环还限制单个子控制器独占控制权的最长窗口，避免流水线控制器在持续压力下饿死分发控制器。

三轮平衡负载中，自适应分发相对冻结基线的中位吞吐为 `894,697` 对 `900,855 pages/s`，代价 `-0.68%`；背压事件中位数 `140,471 → 97,441`，下降 `30.63%`，Runner 平均核心中位数 `116.17 → 114.31`。三轮均 `failed=0`。这说明正常均匀负载下没有虚构吞吐收益，但负载分发更平滑，额外成本控制在 1% 内。

在固定压制 NUMA 0 的 40M 扰动对照中，自适应吞吐 `654,925 → 667,577 pages/s`，提升 `1.93%`；背压 `565,961 → 439,440`，下降 `22.36%`，仍为零失败。仅 `65,170/40,000,000` 个任务跨 NUMA，占 `0.163%`，证明 stealing 是饥饿恢复路径而不是常规调度路径。

## 实现

### NUMA 内分片入口

- 每个 NUMA 节点保留多个 Reactor 对应的有界 lane，避免把所有生产者重新汇聚到单个节点级 MPMC 热点。
- 每个内容 Worker 有稳定的主 lane；主 lane 空闲时先检查同 NUMA 其他 lane，并按当前批量领取。
- 任务携带源 NUMA 和原 Reactor 的缓冲回收通道；即使被其他节点处理，缓冲仍返回原所有者。
- 内容 Worker 使用节点内全局编号，因此统一流水线控制器的活跃 Worker 配额现在真实作用于每 NUMA 节点，不再因 Reactor 内编号重复而失效。

### 自适应闭环

拓扑初值根据每 NUMA 内容 Worker 数计算。在本机 36 Worker/NUMA 时从批量 2、连续 4 次本地空轮询后允许 stealing、跨节点批量 1 开始；这些是拓扑函数结果，不是 Xeon 常量。

控制器观察：

- 完成吞吐与 PageSift Runner CPU；
- 总队列深度、节点间队列不平衡和队列背压率；
- steal 尝试、命中和实际跨节点任务比例；
- 请求失败率。

平衡负载优先挑战更小批量；只有真实队列压力才向更大批量扩张。挑战拥有完整稳定窗口，不允许瞬时队列采样把一次相邻挑战扩展成连续扫描。流水线比例和任务分发参数串行取得控制权，避免同时改变两个维度造成错误归因。

## 单 NUMA 扰动结果

验证时在 NUMA 0 的 24 个物理线程上运行独立 CPU 干扰进程；固定和自适应使用相同方法、同一源站及相同 40M 负载。干扰进程和同机源站 CPU 均不计入报告的 Runner CPU。

| 模式 | 吞吐 pages/s | Runner 平均核心 | 背压 | 同节点互助任务 | 跨 NUMA 任务 | failed |
|---|---:|---:|---:|---:|---:|---:|
| 固定 | 654,925 | 82.96 | 565,961 | 0 | 0 | 0 |
| 自适应 | 667,577 | 82.93 | 439,440 | 297,074 | 65,170 | 0 |

自适应运行先完成相邻批量挑战，在压力窗口短暂尝试批量 4，退化后返回批量 2 并锁定；测试结束时正在对批量 1 做一次低频相邻复探。完整调整序列保存在 JSON 中，因此“结束时 Settling”不是持续扫描。

## 边界

- 4.3 只解决已完成响应正文在内容执行阶段的入口争用和局部算力不平衡；DNS、TCP/TLS、HTTP、解析和输出的独立容量窗口属于 4.4。
- 平衡负载的目标是接近零成本，而不是强行制造吞吐提升；本次中位代价为 `0.68%`。
- 跨 NUMA stealing 不迁移 Socket，也不改变连接所有权；它只移动已完成网络接收的正文任务。
