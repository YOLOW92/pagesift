# 0.89 — Egress pool and robots-ignore audit

**Scope.** Named egresses (`[[egress]]`) gain a `class`. With two or more configured, requests that do not name an
egress are routed by an `EgressPool` that learns, per site, which egress gets denied. Browser rendering uses the same
egress through a per-context proxy. Requests that actually ignore robots.txt are written to the audit log.

## Configuration

```toml
[[egress]]
name = "dc-1"
proxy = "http://user:pass@dc1.example:3128"
class = "datacenter"      # datacenter | residential | mobile | direct (default)

[[egress]]
name = "home"
class = "direct"          # no proxy: same network settings as the default egress
```

- Configurations without `class` load unchanged (`direct`). Non-`direct` classes require `proxy`.
- Zero or one named egress: no pool; a request without `egress` uses the default egress as before.
- A request that names an egress (`egress`, or `proxy` set to a name or proxy URL) always uses it; its outcome is
  recorded, it is never switched.

Code: `crates/pagesift-policy/src/egress/` (rules and selection in `mod.rs`, tables in `stats.rs`), routing in
`crates/pagesift-engine/src/engine/egress_route.rs`, browser proxy in `crates/pagesift-cdp/src/proxy.rs`.

## Guardrails

| Guardrail | How it holds |
|---|---|
| Politeness budget per site, shared by all egresses | A switched retry goes through the same per-host limiter and cooldown; at most one switch per request |
| 429, 503 + Retry-After, rate-limit pages back off and never switch | `Outcome::Throttled` → `Action::Backoff`; not counted in the denial posterior |
| robots.txt per site, independent of egress | `RobotsCache` keys by origin and fetches through the default egress |
| No CAPTCHA solving, no fingerprint spoofing, honest User-Agent | User-Agent does not change with the egress; a challenge page gets one switch, then is reported |
| A site's cookie session stays on one egress | Requests with a `Cookie` header or administrator-configured cookies for the host are bound to the first egress used for that site and never switched |

## Block classification

| Outcome | Signal | Action |
|---|---|---|
| Throttled | 429; 503 + Retry-After; barrier rule id containing `rate` | back off, keep the egress |
| Blocked / Unreachable | 403, barrier `block`; network, upstream, timeout errors | denial; switch once if IP reputation is significant |
| Challenge | barrier `challenge` or `captcha` | denial; switch once, preferring another class; a second challenge is reported |
| Site-wide | ≥ 2 egresses tried and each one's Wilson lower bound (δ) of the denial rate > ½ | reported (`details.egressPool.verdict = "denied_on_every_egress_tried"`), no switch |
| Neutral | 401, 451, other 4xx/5xx, login walls, interstitials, caller errors, host cooldown | not recorded |

**IP reputation test.** Denial rate of (site, egress) against the same site on all other egresses pooled, one-sided at
level δ, Agresti–Caffo adjusted (Agresti & Caffo, *The American Statistician* 54(4), 2000): switch iff
`p̃₁ − p̃₂ > z(1−δ)·√(Var₁ + Var₂)`. Only the site's own counts are used. With no data on another egress the test cannot
pass, so a first denial is never attributed to the egress.

## Selection

Thompson sampling (Thompson 1933): draw `p̃_e` from the Beta posterior of `P(denied | site, egress)` and pick
`argmin_e 2·p̃_e + λ_e`; 2 is the cost of a denial in service times (wasted fetch plus retry),
`λ_e = 1/(1−ρ_e)` is `pagesift_stat::decide::shadow_price` with `ρ_e` = in-flight requests on the egress over its equal
share of the global concurrency limit. A saturated egress is used only when every candidate is saturated.

- **Shrinkage** (empirical Bayes; Robbins 1956, Efron & Morris 1975): class prior = method-of-moments Beta fit
  (`pagesift_stat::shrink::beta_prior`) over the (registrable domain, egress) cells of the class; domain level = class
  prior plus domain counts minus the site's own; site prior centred on the domain mean with the class prior's
  strength, capped at `N_eff`. Cold start is `Beta(1,1)`.
- **Forgetting** (discounted Thompson sampling; Raj & Kalyani, arXiv:1707.09727, 2017): each observation at a site
  first multiplies that site's and domain's counts by `γ = 1 − 1/N_eff`, `N_eff = z(1−δ)²·¼/δ²` ≈ 271 at δ = 0.05
  (Cochran 1977 §4.4). A denied egress's evidence fades while others serve the site, and it is re-sampled.
- **Tables.** Sharded by registrable-domain hash (one lock per selection), shard count = next power of two ≥ logical
  CPUs, shards and in-flight counters 128-byte aligned; class priors in atomics, refit amortised O(1); per-shard site
  cap from a memory budget (default 8 MiB), eviction to half, non-cookie-bound sites with fewest observations first.

## Browser rendering through the egress

- Each rendered page has its own browser context; with an egress it is created with
  `Target.createBrowserContext { proxyServer, proxyBypassList: "<-loopback>" }` (the bypass entry removes Chrome's
  implicit loopback exemption). If that fails the render fails; it never falls back to direct.
- Proxy credentials are answered via `Fetch.authRequired` (`handleAuthRequests`) only for `source = "Proxy"`.
- Only Chrome supports per-context proxies; other engines are skipped for such requests. `render_skipped_egress`
  remains only where the browser cannot use the egress at all (no Chrome in the chain, or a SOCKS proxy with
  credentials, which Chrome cannot authenticate); `engine: "browser"` is refused in those cases.

## robots.txt ignore audit

- Single-page scrape and each crawled page: the scrape record gets `robotsIgnored: <reason>`.
- Crawl and map: one `kind: "robots_ignored"` record with `url`, `request`, `reason`.
- Caller is `client` as in every audit record; URLs are redacted as usual.
- Reasons: `ignoreRobotsTxt`, `ignoreRobotsTxt+allow_crawl_ignore_robots`, `respect_robots=false`.

## Tests

`cargo test --profile release-fast --lib` (2026-11-03):

| Crate | Tests | Result |
|---|---|---|
| `pagesift-policy` egress module | 11 | all pass |
| `pagesift-cdp` proxy parsing | 1 | pass |

Egress module tests (synthetic, fixed seeds):

- IP ban (denial 0.95 on one egress, 0.02 on the other): the first denial with no comparison data keeps the egress;
  with alternating samples the switch becomes significant within 10 requests; denial posteriors converge to within
  0.08 of 0.95 and below 0.08; in the adaptive phase ≥ 295 of 300 requests end on the unbanned egress; a second site
  with no ban is unaffected.
- Throttling: 500 throttled reports, every one `Backoff`, posterior unchanged.
- Challenge: 50 sites, every challenge switches once to a different class; a second challenge never switches again.
- Site-wide denial (both egresses deny everything): ≥ 90 of 100 requests reported as site-wide, ≤ 5 switches.
- Cookie session: 200 cookie-bearing requests stay on the bound egress, never switched, even when blocked.
- Re-probing: after a ban is lifted, the formerly banned egress serves ≥ 100 of the last 1,000 of 8,000 requests.
- Shadow price: with one egress saturated, 50 of 50 selections go to the idle one.
- Cold start: posteriors and class priors are `Beta(1,1)`; a single-egress pool never switches.
- Class prior: over 200 domains, estimated class means are within 0.08 of 0.30 and within 0.05 of 0.05.
- Memory bound: 20,000 sites with a 64 KiB budget stay within the per-shard cap.
- `Policy`: no pool with zero or one named egress; a pool with two.

Integration test `crates/pagesift/tests/scrape.rs::egress_is_used_for_http_and_for_browser` (egress pointing at a
dead proxy; HTTP and `engine: "browser"` must both fail rather than reach the page directly): pass. It first failed
because Chrome never proxies loopback addresses by default; the context is now created with
`proxyBypassList: "<-loopback>"`, so every request goes through the egress. `pagesift-cdp` lib tests: 35 pass.
