# 0.85 — Inputs and outputs

New crate `crates/pagesift-sink`: output envelopes, metadata keys and the cache format live in one place.

## Metadata keys

The content layer's metadata used to be mapped to output keys in three places that disagreed: the engine
(Firecrawl `metadata`), the Node `convert` (no `author`) and the Python `convert` (raw `og:image` keys, no `author`
in the getter). There is now one mapping, `pagesift_sink::meta`:

| Entry | Keys |
|---|---|
| scrape (HTTP API, MCP, CLI, py, node) | Firecrawl camelCase (`ogImage`), unchanged bytes |
| node `convert` | same keys as scrape (adds `author`) |
| py `scrape` and `convert` | snake_case of the same keys (`og_image`); `author` added to the getter; `convert` keeps `canonical_url` |

## Cache format

Cached documents are stored in a self-describing binary encoding (`pagesift_sink::codec`: type tags, LEB128
lengths, zigzag integers, `END`-terminated maps and sequences) behind a 4-byte magic and a format version. Strings are
length-prefixed bytes, so reading a cache hit does not scan for or undo JSON escapes. A wrong magic, another version or
truncated data reads as a miss. The cache key's first element moved from 1 to 2, so 0.84 JSON entries are never read.

The cached document now keeps the two fields that are not part of the Firecrawl JSON (anchor texts of `links`,
`hreflang` alternates). Before, a crawl that hit the cache lost anchor texts for link scoring.

## Command-line outputs

`scrape`, `crawl` and `convert` share one directory layout under `--out` (one `.md` per page, one `index.jsonl` line
per page, `summary.json` at the end of a crawl). `scrape --warc` and `crawl --warc` write ISO 28500 WARC/1.1: per page a
`resource` record (the page HTML, decoded to UTF-8 — pagesift does not keep the original bytes and headers, so it is
not labelled as a `response`), a `conversion` record (Markdown) and a `metadata` record (Firecrawl `metadata` JSON),
the last two pointing to the first with `WARC-Concurrent-To`. A `.gz` file name writes one gzip member per record.

`collect`, `session-fetch` and the media commands keep their own outputs: they produce API items and media files,
not pages. `collect`'s event log is its sink, with the same acknowledgement semantics.

## HTTP API

| Endpoint / event | Behaviour |
|---|---|
| `GET /v2/crawl/{id}/stream`, `GET /v2/batch/scrape/{id}/stream` | SSE by default (`event: page`, `id:` = index in the polling list, `data:` = the same document JSON as polling); `Accept: application/x-ndjson` gives one `{"seq","type":"page","data"}` per line. `?cursor=` or `Last-Event-ID` resumes after that index. Pages are pushed when they complete (change notification, no polling); `event: done` with `status`, `completed`, `total` ends the stream. A keepalive is sent after 30 s without events (half of nginx's default `proxy_read_timeout` of 60 s): `: keepalive` for SSE, `{"type":"keepalive"}` for NDJSON. |
| Jina reader SSE | Headers are sent immediately and each frame (progress, content segments, done) is written as soon as it exists; the concatenated bytes equal the previous implementation. A failure after the headers are sent is reported as `event: error`. |
| Webhooks | Each event carries `eventId` (`"{job}:{seq}"`) and `seq` (from 1 per job). With a store, events are written before delivery and an acknowledged cursor is kept, so a restart resumes after the cursor and numbering continues. Without a store, or after a store error, events go to a bounded in-memory queue that applies backpressure; page events are no longer dropped when the queue is full. An event can be delivered twice if the process stops between delivery and acknowledgement; receivers can deduplicate on `eventId`. |

## Tests

- `pagesift-sink`: codec round trip with flatten, options, enums and JSON values, errors on truncation; cache round
  trip including the non-JSON fields and rejection of JSON / other versions / truncated data; metadata keys; WARC
  record types and links.
- `pagesift-api`: webhook with a one-slot queue and 40 concurrent page events (all delivered, in order); restart
  resumes after the acknowledged cursor; store failures fall back to memory; stream pushes on completion, resumes
  from `cursor` and `Last-Event-ID`, NDJSON, keepalive; Jina stream bytes equal the previous output.
