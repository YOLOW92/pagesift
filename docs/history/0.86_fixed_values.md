# 0.86 — Fixed values replaced by estimates

Rule for every replacement: with no observations the behaviour equals 0.81.5 (the old value is the prior, with
the weight of one observation); an estimate replaces the current value only when the difference is larger than
`z(1−δ)·SE` (δ = 0.05); user settings, safety limits and protocol values stay hard limits. Statistics are kept
per thread or in sharded tables (shard count grows with the core count, at least `1/δ` entries per shard) and
are read with one atomic load on the request path.

## Control plane

| Value (0.81.5) | Now |
|---|---|
| `TuningProfile` tiers, `AutonomousTuningEngine`, `diagnose` thresholds, surface/AIMD controllers, `MemGuard` 10/12 GiB | removed. `--tuning-mode` is accepted and ignored (noted on stderr); `diagnose`/`tune` report the hardware, the memory budget and the cold-start values |
| global concurrency 64 | Universal Scalability Law fit of throughput against in-flight requests; target = lower `1−δ` confidence bound of `N*`. Cold start 64 (`crawl`: the 0.81 crawl formula, `max(16·CPUs, 24·local physical cores)`, bounded by memory and file descriptors). `global_concurrency` in the config is a hard ceiling |
| per-host concurrency 2 | latency-gradient limit over concurrency levels (`limit ← limit·RTT_base/RTT_now + √limit`, Netflix Gradient2 / TCP Vegas): latency is kept per concurrency level and the limit moves only when adjacent levels differ significantly; when latency reaches 1.5 × the unqueued latency (the 0.81 threshold) the limit drops one level at once. Cold start = the user value (2), capped by `⌈upper RTT bound / request interval⌉` (Crawl-delay); 429 only lengthens the interval, as in 0.81 |
| `host_connections` warm-connection target, EWMA and slow-request thresholds | unchanged from 0.81.5 |
| `max_body_bytes` 15 MiB | `min(user value, memory budget / in-flight target)`; cold start = user value |
| MCP and API batch concurrency 8 | the global in-flight target, capped by `max_batch_concurrency` |
| rate-limit penalty 250 ms … 30 s, ÷2 decay | bisection between the largest interval that was refused (429) and the smallest that passed; `Retry-After` first |
| limiter table cleanup `max(interval, 60 s)`, `PRUNE_AT` 4096 | entries whose interval or penalty is still active are kept; others are dropped lowest-information first |
| statistics sample interval 1 s | update every `⌈target⌉` completions |

Unified admission facade for CPU workers, network in-flight requests, browser tabs and memory:
`pagesift_flow::admit`. The network wait rule (below) reads its shadow price `ρ/((1−ρ)·W)` from it.

| backoff threshold 3, base 10 s, cap 600 s | Kaplan–Meier outage duration, retry when the recovery probability reaches `1−δ`; `Retry-After` first. With politeness on, the cooldown is never shorter than the 0.81 exponential backoff |

## Browser and rendering

| Value (0.81.5) | Now |
|---|---|
| render timeout 30 s, launch 20 s, idle close 60 s / fallback 15 s | one rule: among renders still running at `t`, the fraction that finish before the old limit; when its Wilson upper bound falls below δ the limit moves down to `t`. One render in 20 runs to the old limit so the limit can move back up; never above 0.81 |
| navigation patience, early stop, render budget: mean + 3σ once SE ≤ 10 % | upper `1−δ` confidence bound of `q(1−δ)` (order-statistic bound), published per window when the window's relative SE < δ |
| per-engine memory table (MB per browser and per tab) | measured at run time: PSS of the browser's process tree (`smaps_rollup`, children followed through `task/*/children`); per browser = window mean of idle-browser PSS, per tab = window ratio of (PSS − per-browser) to tabs in use; the 0.81 table is the prior. Admission's memory check uses the measured values |
| `min_available_memory_mb` 1024 | memory used by the rest of the system (MemTotal − MemAvailable − own browsers' PSS); upper confidence bound of `q(1−δ)` of its change between samples, never below the footprint of one more browser; prior 1024 MB; 0 still disables the check |
| browser tab slots | taken through the unified admission (`pagesift_flow::Admission`); the limit is the sum over pools of the USL target × tabs per process. `max_tabs` 4 and recycle-after-100 stay as the starting values |
| fallback browser pool size | starts at the 0.81 size and is adjusted by the USL limit, probing upward only while requests queue |
| browser `Accept-Language` | the same header as HTTP fetches (`en-US,en;q=0.9,zh-CN;q=0.8,zh;q=0.7`), so a page renders in the language its HTTP fetch saw |
| launch retry 600 s | Kaplan–Meier outage duration |
| minimum attempt 500 ms | lower confidence bound of `q(δ)` of the time to a document, per engine |
| pool hill climbing (gain 1.03, idle thresholds, step cur/8) | USL limit over completion windows (the first window 3 s, then ⌈target × tabs per process⌉ completions) |
| memory recheck 250 ms | mean tab occupancy / tabs in use |
| queue warning (≥ 10 ms) | warn when politeness pacing (request interval or Crawl-delay) made the request wait longer than its own fetch or render time; short waits for a concurrency slot are only reported in `timings.queue` |

## Crawl and content

| Value (0.81.5) | Now |
|---|---|
| Wilson z 1.96 | `pagesift_stat::beta::wilson` at δ/2 per side |
| sleep 1 s after `accept` errors | retry when any connection closes; 1 s only without a notification |
| store maintenance ≥ 1000 ms | maintain again when garbage or size grew by δ of the last total; 1000 ms is the longest interval |
| download checkpoint every 1 MiB | Young–Daly interval; MTBF prior back-computed so the cold start is 1 MiB |
| focus link scoring: five linear weights (anchor, locator, context, parent, phrase bonus) | online Bayesian logistic regression on whether the linked page was a hit (diagonal Laplace, Chapelle & Li 2011); prior mean = the 0.81 weights with the weight of one observation; the weights in use change only when the posterior differs by more than `z·SE` |
| focus harvest interval, phrase detection | harvest interval at the global δ; a phrase counts when its Poisson tail probability passes Benjamini–Hochberg at δ |
| host marked dead after 3 failures | sequential probability ratio test on the host's failure rate, updated only towards more tolerance |
| crawl retries 2, 500 ms | retry while the Wilson upper bound of the success rate of retries for that failure class is ≥ δ; the count stays a safety limit |
| sitemap depth / files / 50 MB | crawl limit decides how much is read; 50 MB is the sitemaps.org limit |
| Office conversion timeout 30 s | per CPU worker, a log–log regression of conversion time on input bytes; after `⌈ln δ / ln(1−δ)⌉` = 59 conversions the limit is the prediction upper bound `exp(β̂₀ + β̂₁·ln b + s·z(1 − δ/n))` (linear beyond the largest input seen). Before that, the request deadline or 30 s as in 0.81. PDF parsing uses the same form with a prior from 1 859 recorded 0.81.5 parses |

Every crawl now reports a summary (`limit_reached`, `exhausted`, `cancelled`); the HTTP API response shape is
unchanged.

## Tests

- Module tests in `pagesift-stat` (estimators, survival, USL, gradient limit, size–time regression), `pagesift-net`,
  `pagesift-policy`, `pagesift-cdp` and `pagesift-flow`: every replaced value equals the 0.81.5 value with no
  observations, and control loops do not oscillate under a step load. The 0.81.5 `host_connections` and
  `host_latency` tests pass unchanged.
- Output on the local comparison set and the cache round trip: see `0.84_data_and_execution.md`
  (`results/20261103-114343`, `results/cache-20261103-131605`).
- Speed, 0.81.5 and 0.90.0 interleaved in the same session: single-request p50 3.96 → 3.99 ms (lower is better),
  16 concurrent requests 792 → 839 pages/s, median of 9 rounds (higher is better)
  (`results/speed-20261103-132110`, `results/speed-stages-20261103-1325`).
