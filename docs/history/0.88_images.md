# 0.88 图片：识别与按原编码导出

日期：2026-11-02。代码：`crates/pagesift-pdf/src/image/`（mod、export、png、tiff、jbig2）、`crates/pagesift-office/src/media.rs`。不做 OCR。

## 识别

- **PDF**：每次画图（图像 XObject、内联图像 `BI…EI`）记页码、位置大小（PDF 点，左上原点）、像素尺寸、位深、色彩空间、编码（jpeg / jpeg2000 / ccitt / jbig2 / pixels）、编码层字节数、SHA-256；同一对象或同一内容只记一条，位置都列上。
- **扫描页**（沿用 0.81 的判定：图覆盖 ≥ 30%、字 < 32 个）：Markdown 写 `*Page N is a scanned image with no text layer.*` 加 `![](images/<哈希前 32 位>.<扩展名>)`。用英文句子，理由：产品的其他输出（警告、Markdown）都是英文；文字在 `page.rs::scan_note` 一处。
- 默认只识别扫描页上的图（不解压其他图像、不算哈希，速度不受影响）；`ImageOptions { list, markdown, export }` 打开后识别全部、按阅读顺序在 Markdown 放引用（同一张图只引用第一次出现）、导出字节。
- **Office**：`pagesift_office::media(bytes, format, &opts)` 列出 docx/pptx/xlsx 的 `*/media/*` 和 EPUB 清单里的图片：部件路径、格式（按文件头）、字节数、SHA-256、位置（docx 正文第几段/页眉页脚，pptx 第几张幻灯片——与 `<!-- Slide N -->` 同号，xlsx 工作表名和锚定单元格如 `AB3`，EPUB spine 第几个文档）；未被引用的也列上。`media_bytes(bytes, part, &opts)` 原样取出。

## 导出与校验

| 编码 | 输出 | 做法 | 校验（B3 100 份，共 324 次识别、118 个去重文件） |
|---|---|---|---|
| JPEG | .jpg | 原样（检查 SOI） | 25 个，`file` 认出 JPEG，Pillow 全部能解 |
| JPEG 2000 | .jp2 / .j2k | 原样；有 JP2 签名框为 .jp2，裸码流为 .j2k | 3 个，`file` 认出，Pillow 能解 |
| CCITT | .tif | 套 TIFF 6.0 头：T.6 → Compression 4，T.4 → 3（T4Options 位 0/2），WhiteIsZero，BlackIs1 与 /Decode 反相时取 BlackIsZero | 3 个（含 8992×10384 的 G4），`file`、Pillow 都能解 |
| JBIG2 | .jb2 | T.88 附录 D 文件头（顺序组织、1 页）+ /JBIG2Globals 段 + 本页段 + 页尾段 + 文件尾段，逐段读段头核对结构 | 2 个；本机 libmagic 没有 JBIG2 条目（误认为 OpenPGP），Pillow 不支持；用 MuPDF（jbig2dec）打开成功，399×400 与 PDF 里的尺寸一致 |
| 无损像素 | .png | 自写 PNG（IHDR/PLTE/IDAT/IEND，CRC-32 自写，zlib 用已有的 miniz_oxide）；灰度/蒙版保持位深，调色板转 PLTE，CMYK 按朴素公式转 RGB，Lab/多分量 DeviceN 不导出（`export_error` 写原因） | 与 MuPDF 解出的像素逐字节比较：216 个**完全一致**，75 个同尺寸多图无法一一对应未比，0 个不一致 |

模块测试：PNG 的 CRC 标准值（"123456789" → CBF43926、IEND → AE426082）、逐块 CRC 与块顺序、扫描线回读；TIFF 文件头、IFD 升序、各标签值和条带偏移；JBIG2 段头解析、越界拒绝、补的页尾/文件尾段编号与页关联；Office 四种格式的位置；集成测试里扫描页的说明、图片表和 PNG 导出。

## 接口

- `PdfImage`：`hash`（SHA-256）、`extension`、`bytes`、`data`（导出时）、`export_error`、`placements`；`PdfImage::file_name()` 为 `<哈希前 32 位>.<扩展名>`，Markdown 里的引用是 `images/<文件名>` 相对路径。
- Office：`Media::file_name()`（同一规则）和 `media_bytes`。
- 这些是 `pagesift-pdf`、`pagesift-office` 的库接口；本次 CLI、HTTP API、py/node 和抓取引擎都不调用它们。

## 没做 / 取舍

- 网页图片（srcset、懒加载、追踪像素）由 `pagesift-content` 处理，本次没有改动。
- 软蒙版（/SMask）不合成 alpha；CMYK 没有 ICC 换算；16 位样本导出成 8 位。
- 内联图像的命名色彩空间（指向资源）读不到，记为 Other，不导出。
