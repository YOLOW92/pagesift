# PageSift 0.70 P2 Step 4.5：分阶段自适应与 100,000 真实网站门禁

> 日期：2026-10-25  
> 环境：Google Cloud `c4-highcpu-192`，Intel Xeon Platinum 8581C，192 vCPU / 96 物理核 / 2 Socket / 4 NUMA  
> 判定：Step 4.4 与 Step 4.5 通过。正式集合严格完成 `100,000/100,000`，五阶段控制器没有容量塌缩，策略拒绝未触发全局降并发，完整 workspace 测试通过。

## 实现边界

生产 `Scraper -> Policy -> pagesift-net -> Rustls -> content` 路径已由单一总并发拆成五个取消安全的独立容量域：

1. DNS：正/负 TTL 缓存、同域 Singleflight、瞬时错误有限重试，缓存命中仍重新执行 SSRF 地址校验；
2. TCP/TLS：Happy Eyeballs 交错竞速、独立握手容量、连接复用，证书及确定性协议错误不重试；
3. HTTP：独立 TTFB/body 遥测，429/503 作为过载信号，连接失败不再误伤 HTTP 容量；
4. 解析：HTML/PDF 解析使用独立容量，不让网络等待占用内容线程；
5. 长尾：超过阈值的响应主动从 HTTP 槽转入有界长尾槽，取消和超时会记账，不能伪装为完成。

DNS、TCP、TLS、TTFB、body idle 使用分阶段 deadline。自适应配置随硬件档位生成；本机为 DNS/TCP `3.5s`、TLS `3.5s`、TTFB/body idle `8s`、长尾阈值 `2s`。控制器使用带迟滞的事件驱动 AIMD：持续的异构公网失败只允许一次回退，健康窗口重新武装，避免旧实现把容量反复压到最小值；不存在手工网格和永久扫描。

robots 继续遵守 RFC 9309，增加跨批次缓存、ETag/Last-Modified 条件请求与 304 复用。`Disallow`、SSRF、访问屏障及确定性失败仅记账，不教授全局容量，也不因成功率目标而绕过。

## 四层归因

| 层 | 冻结证据 | 结论 |
|---|---:|---|
| 内容纯 CPU | Step 4 三轮中位提升 `10.29%` | 解析已优化，但不是公网主瓶颈 |
| 固定本地完整链路 | Step 4.1 长窗口最高 `929,472 pages/s`、`failed=0` | 本机 Reactor/分发可在本地数据面激活约 123 个逻辑核 |
| 主机连接生命周期 | Step 4.2 慢 host 成功吞吐 `3.44x`、503 中位 `-96.71%` | host 局部过载可独立收敛，不应拖累其他 host |
| 真实公网生产路径 | 本次 `121.89 tasks/s`、平均 `1.64` 核 | 主要受公网 RTT、失效域名、策略检查与远端长尾限制，不是 192 vCPU 没有被调度器开放 |

这些层不能互换口径：本地生成页面用于定位可控数据面，公网集合用于验证生产成功率、协议和长尾。公网低 CPU 不能反推本地 Reactor 或解析器吞吐不足。

集合为 `benchmarks/data/top-1m.csv` 的前 100,000 个不同规范化目标，每 host 仅访问首页一次。规范化 BLAKE3 为 `173d2c6519ba5e8ba3144dc9179543de4e3663979ec854942f6aaeb26b476542`，已写入 manifest 与正式 JSON。

| 成功页面 | `60,761`（`60.761%`） |
