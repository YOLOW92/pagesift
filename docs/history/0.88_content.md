# 0.88 正文提取：误删的小标题和文章标题

## 做了什么

在 Firecrawl 集的一半题目上逐页查"整页输出里有、正文输出里没有"的正文短语，找出被跳过规则误删的块，
按类别修。改了三处，都在 `crates/pagesift-content`：

1. **小标题的锚点 id 不当类名看**（`classes.rs`、`extract.rs`）。文档站和 Markdown 渲染器按小标题文字生成
   `id`（`## Not Recommended: …` → `id="not-recommended-…"`），id 里碰巧有噪声词（recommended、sharing、
   related、recent……）时整个小标题被当框架删掉。现在 `<h1>`–`<h6>` 的 id 如果每个词都出现在标题文字里
   （纯数字的去重后缀不算），这个 id 不参与类名判断；class 照旧判断，不是按文字生成的 id（`related-posts`）照旧判断。
2. **自锚点小标题不当链接块**（`article.rs`）。文章模式的链接密度规则会删掉"文字全是链接"的短块；
   标题文字本身就是指向本节锚点（`href="#…"`）的小标题因此被删。现在块的可见文字全在小标题里、
   里面的链接全部指向本页锚点时不算链接密集。指向别的页面的标题链接（推荐卡片）照旧删。
3. **补标题时优先用和文档标题一致的 `<h1>`**（`article.rs`）。文章主体外面没有可见 `<h1>` 时原来用
   `<title>` 补标题；`<title>` 常拼着栏目和站名（"标题 - 栏目 | 站名"）。现在页面上有和文档标题一致的
   `<h1>`（哪怕它在被删掉的页头里）就用它的文字。

## 试过、退回的

- **严格规则连同署名栏删掉主体里的 `<h1>` 时，把标题补在最前面**：Firecrawl 调参半多找回一页的标题，
  但 AEB 有 3 页因此多出标题（AEB 的标准答案不含标题），合并 F1 −0.0003，单侧上界 < 0，不满足"不降"；
  另有一页把站点标志的 `<h1>`（"CNN"）补成了标题。退回。
- **对所有页面都尝试文章模式**（不再先排除"明显不是文章"的页面）：WebMainBench 调参半 +0.032
  （95% 区间 [+0.010, +0.057]），但 Firecrawl 调参半 −0.030（[−0.069, −0.001]）、AEB −0.0014。
  两套标注对非文章页（商品页、列表页、落地页）的口径相反：WebMainBench 只要主块，Firecrawl 要页面上除框架
  以外的全部内容。不改。

- **按路径族删同族页面上逐字重复的块**：进程内按路径族（来源 + 首级路径）记下每页块级元素的文字指纹，
  处理同族下一页时，块在族里其他页面上出现比例的后验 `Beta(1+k, 1+n−k)` 单侧 5% 下界超过 1/2 就当页面框架删
  （族里没有其他页时与原来一样）。在 WebMainBench 全集 7,809 页里同一路径族至少 5 页的 297 页上，按文件顺序
  逐页处理（每页只看得到同族前面的页），词级 F1 不给族 0.8908 → 给族 0.8844（Δ −0.0063，[−0.0156, +0.0006]），
  精确率 0.8687 → 0.8715。下降主要在数据表的表头行和同类商品页共有的说明（WebMainBench 把它们标为正文）。
  改成表格里、`<article>`/`<main>` 里的块不删后再测一次：0.8908 → 0.8885（Δ −0.0022，[−0.0048, −0.0001]），
  仍下降（主要是专利页的著录项目）。退回，结果在 `benchmarks/history/0.88/content/results/family-template-reverted.md`。

## 怎么测

- 集：A1 的 AEB、Firecrawl、WCXB、WebMainBench 各 150 页，输入与 0.81 质量轮相同；每页
  `pagesift convert <文件> [--base-url <原始 URL>]`，默认配置。
- 评分：沿用 `benchmarks/mix/score_quality.py`（AEB 用 evaluate.py 的合并 F1，Firecrawl 用正文召回，
  另两套用词级 F1；全部越高越好）。Firecrawl 集两边都用 0.81.5 的 `bench --external` 打分。
- 判定：新旧逐页配对 bootstrap，δ = 0.05；"提升" = Benjamini–Hochberg 校正后单侧显著且 95% 区间下界 > 0，
  "不降" = 单侧 95% 上界 ≥ 0。题目按 id 的 SHA-256 首字节奇偶分两半：分析漏掉的块只看调参半，保留半只用来验证。
- 旧：0.81.5 发布的二进制；新：本次改动的 `release-fast` 构建。三处改动合在一起，全部改完后只跑一次。
- 脚本：`benchmarks/history/0.88/content/`（`run.sh`、`run_a1.py`、`paired.py`），结果在 `results/`。
