## 5. 本步骤发现并修复的严重性 BUG（B 级：资源不收敛）

**现象**：全量抽取在 `track_id 2bdea22c-df8e-4f4b-896e-2bb3037889bf`（`https://help.windev.com/?1013105`，416 KB HTML）上**永久空转**，单核 100% 无限运行，无输出、无报错。本机另一次全量在第 4138 行被 OOM 杀死（`exit=137`）。

**根因**：`pagesift_content::markdown::Renderer` 的嵌套 `<table>` 重复渲染。

- 该页有 **241 个 `<table>`，最大嵌套 **27** 层，88 个 table 块中 52 个含内层 table。
- `table()` 渲染单元格时调用 `blocks_of(cell)`，而单元格内的内层 table 又进入 `table()`；`table()` 在"单行/单列排版表"时又回退 `blocks_of(node)`。两条路径互相回流，`block()` 调用数单调发散——实测被探针在 **2,000 万次**调用处截断仍未收敛，代价随嵌套深度指数增长。

**修复**（`crates/pagesift-content/src/markdown.rs`，+22/−2）：给 `Renderer` 增加 `flat` 状态；进入单元格或排版表回退时切到 `as_flat()`，此后 `block()` 命中 `"table" if self.flat => blocks_of` 分支，内层表格只透传文字、不再展开成子表。

**验证**：
- 该行从"无限空转"变为 **3.2 ms 渲染、约 39 KB 正常输出**。
- `pagesift-content` 全部 **117 个测试通过**，零回归。
- 全量 7,809 页在 5.0 s 内跑完，0 hang、0 错误。
