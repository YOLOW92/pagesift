# 正文区域的标题归属约束

自研 Rust 正文核心增加了两类边界证据，避免单凭“文字最多”或“全页第一个 H1”挑正文。

1. 标题应属于当前文章。正文所在 article 的 H1，或其 header / headline H2，可以作为本篇标题；其他 article 中的 H1 不会把正文范围扩大到推荐列表。若真正标题在 article 外，且与文档 title 一致，则单独保留标题，不向外扩张正文容器。
2. 文档 title 与文章标题对应，且 article 有充分段落正文时，优先保留这一完整 article。这样即使推荐区域文字更多，也不会因此改选推荐区域；文章结尾较短的独立章节也不会在最大子块下钻时丢失。

标题匹配采用规范化文字直接包含，或长度大于两个字符的词集合覆盖至少 80%。规范化直接匹配支持中文、日文等不依赖空格分词的标题。多个 article 同时符合标题证据时放弃该优先级，回到原有仲裁；标题关联是一种正文选择证据，不是对任意网页身份的保证。

本功能只在既有文章模式中生效，保留主页保护、隐藏元素过滤、导航过滤、正文白名单和非文章页面的一般转换方式。没有站点名、URL、文章 ID 的特殊分支。它不试图通过删掉全部标题或保留全部推荐来优化某一个评测口径。

回归覆盖：正文 H2 与其他文章 H1 的冲突、推荐块在正文前后、比正文更长的嵌套推荐区域、正文末尾短章节、中文标题、article 外的文档标题。正文开发数据之外，新增固定版本的 Mozilla Readability 官方测试页与 expected HTML，按来源组冻结开发/保留拆分；具体结果与未解决项记录在评测报告中。


## 无声明短文与正文附件（2026-10-22）

`editorial.rs` 增加独立的局部结构判断，无域名、文章 ID 或评测 ID 分支。

- 无文章声明的短文：排除已知首页，寻找与文档 title 一致、12–180 个非空白字符且没有链接的短标题；最多向上三层找含直接叙述正文的容器。容器需有 250–3500 个可见字符，链接字符占比不超过 20%，链接不超过 16 个，直接正文至少 200 个非空白字符且至少三个句末标点。多个不同候选同时成立就放弃收窄。这个范围同时用于 Markdown、plain text 和 clean HTML；不修改网页原始的文章声明元数据。
- 商品调用块：在十层以内的 article 上下文中，要求紧凑 product/callout 容器同时包含购买链接以及价格或说明。独立购买链接需要 shop/product/products/buy 路径及紧邻的说明段落和小标题。推荐、赞助、广告、播放列表、工具栏上下文不获得附件豁免。
- 视频：紧凑 figure/video 区域需要真实 video 元素或播放器标识，并同时有 caption/description 证据；保留视频说明时仍执行隐藏元素、控件和推荐过滤。
- 引用：紧凑嵌入引用要求至少 120 个非链接正文字符，链接文字不超过一半。仅有社交加载占位符、链接目录的引用块不会因此恢复。
- 推荐列表：文章模式下，列表至少有三个链接且至少一半链接的查询参数显式带 related/recommend 归因时删除；普通正文提到这些词不触发规则。

附件判断按节点缓存，局部附件最多检查 128 个后代；超出范围保守回到原过滤。此实现不覆盖任意动态播放器，也没有证明无标记正文定位普遍解决：直接正文包在深层 span 或多个段落中的短文可能仍需后续工作。

本次只对新推断短文区域统一了三个输出范围。既有严格文章模式的 plain text / clean HTML 仍沿用原有范围，不应据此声称所有输出已完全一致。

早期完整结果与回退记录保留在本地评测归档；公开的最新对照见 [评测报告](../benchmarks/history/0.70/six/REPORT.md)。AEB 和 WCXB 511 页已用于开发回归；额外 1355 页来自此前未运行的 WCXB dev，和前者仍共享数据集来源，不能称作新的官方独立测试集。
