# PageSift 1.6.3 Release Notes

> **Release Version**: `v1.6.3`  
> **Release Scope**: Fail-closed API configuration & shared-account enforcement, Monitor deletion lifecycle consistency, CDP security-setup fail-closed hardening, revoked-account background execution stops, Cluster quota settlement reconciliation, and fail-closed legacy tenant probing on the `1.6.x` line (`v1.6.2 -> v1.6.3`)

PageSift `1.6.3` is a stability, security, and state-ownership hardening release on the `1.6.x` line that closes configuration, concurrency, CDP interception, background-job authorization, cluster quota settlement, and legacy tenant upgrade edge cases.

## Highlights

- **Single Source of Truth for Shared-Account Validation & Zero-Limit Parity (`pagesift-api`, `pagesift-cluster`, `pagesift`)**:
  - Adds fallible `pagesift_api::try_router(engine, config) -> Result<Router, ApiError>` (used by `pagesift serve`; `pagesift_api::router()` delegates to it and fails closed on invalid `Config`) so direct Rust `Config` construction enforces the same rules as TOML configuration.
  - Rejects conflicting `requests_per_minute`, `max_concurrent_jobs`, or `pages_per_day` across keys sharing an explicit `account`, rejects invalid or delimiter-containing (`/` / `|` / control / reserved-prefix) account IDs in `key_limits` and `default_limits`, rejects `default_limits.account` when authentication is disabled, and rejects duplicate conflicting `[[server.keys]]` entries (including conflicting `name`).
  - Aligns `requests_per_minute: Some(0)`, `pages_per_day: Some(0)`, and `max_concurrent_jobs: Some(0)` behavior identically across the local `Limiter` and `pagesift-cluster::Ledger`.
- **Unified Monitor Lifecycle Ownership & Cancellation-Safe Deletion (`pagesift-api`)**:
  - Replaces the unbounded global `run_locks` map with per-entry `MonitorLife` (`run_lock`, `persist_lock`, atomic `deleted`, and `watch` cancellation channel) under a strict lock order (`run_lock -> persist_lock -> map`), eliminating lock-table growth and cross-monitor blocking.
  - Cancels in-flight URL checks, crawl checks, and webhook deliveries immediately on `DELETE /v2/monitor/{id}`, serializes blocking disk writes (holding `OwnedMutexGuard` inside `spawn_blocking`) against deletion so cancelled `run_now` or `create` calls never resurrect deleted monitors, and surfaces storage delete failures (`500`) instead of returning false `200` responses while keeping deletion retryable.
- **Fail-Closed CDP Security Setup & Non-Intercept Guardrails (`pagesift-cdp`, `pagesift-engine`)**:
  - Enforces pre-navigation rejection of `allowedHosts` and `bypassServiceWorker` on non-intercept engines (`!env.intercept`, while preserving ordinary non-challenge Lightpanda rendering).
  - Eliminates silent `let _ =` swallowing on `Page.addScriptToEvaluateOnNewDocument`, `Network.setBlockedURLs`, `Network.setBypassServiceWorker`, and child-target (`iframe`, child `page`, `worker`, `worklet`, `shared_worker`, `service_worker`) security setup: failures abort before navigation or target resumption, and `wait_event` / `wait_navigation` / `wait_idle` / `wait_ready` / `redirect_page` exit promptly on interception errors.
  - Pipelines `Network.enable`, `Network.setBlockedURLs`, and `Runtime.evaluate` with `Runtime.runIfWaitingForDebugger` for Chromium `service_worker` / `shared_worker` targets after `Fetch.enable` succeeds, preventing Chromium's paused-worker startup deadlock while retaining fail-closed verification.
  - Ensures `[itna]` executes at most one browser fallback per request, reserves non-Chrome navigation budget only when invoking a browser, and propagates `ITNA_EXPECTED_DIRECT` plus same-scheme checks to HTTP iframe inlining.
- **Revoked-Account Background Execution Stop (`pagesift-api`)**:
  - Persisted monitors whose owning account is no longer configured (or when restarting an authenticated store in unauthenticated mode) are paused (`status: "paused"`, `pausedReason: "account_revoked"`) with preserved data, diagnostic warnings, and `pagesift_monitor_revoked_paused_total` metrics instead of falling back to `default_limits`; restoring the account auto-resumes revoked monitors while keeping crash-paused monitors paused, and shared-account key rotation retains uninterrupted ownership.
  - Persisted in-progress `Crawl` / `BatchScrape` jobs belonging to revoked accounts are marked `failed` (persisting `meta.state = Failed` before recording an explanation under `notes`, without inflating `completed` counts) rather than resuming under `default_limits`.
- **Idempotent Cluster Quota Reconciliation & Tri-State Settlement (`pagesift-cluster`, `pagesift-api`)**:
  - Adds idempotent hold closure (`Ledger::close_locked`), stale non-task hold cleanup on UTC day rollover (`QuotaShard::prune`), and bounded single-flight FIFO reconciliation (`pending_ledger`, `AtomicBool` zero-lock hot-path sentinel) plus local `dirty_local` day-rollover pruning and opportunistic flushing.
  - Introduces tri-state `SettleOutcome` (`Confirmed`, `Failed`, `Uncertain`) surfaced on HTTP endpoints (`/v2/scrape`, `/v2/parse`, `/v2/interact`, `/v2/observe`, `/v2/similar`, `/r/*`, `/s/*`) via `quota_settlement_unconfirmed` warnings on recoverable failures, HTTP `500` on unrecoverable failures, and Prometheus metrics (`pagesift_quota_settlement_failures_total`, `pagesift_quota_settlement_uncertain_total`, `pagesift_quota_settlement_dropped_total`, `pagesift_quota_pending_settlements`).
- **Fail-Closed Legacy Tenant Probing (`pagesift-api`, `pagesift-store`)**:
  - Extends startup legacy-tenant discovery to cover `agent/{id}`, `attachment-access/{account}/{id}`, and cluster `Ledger` history while ignoring derived `job/{id}/hook_*` sub-keys and decoding grouped `GRAPH_NODE` / `GRAPH_EDGE` keys in `Store::existing_tenants()`.
  - Fails closed instead of silently switching to a blank SHA-256 namespace when store reads fail, persisted metadata records are corrupt, or both legacy FNV-1a and SHA-256 namespaces hold data for the same key (resolvable by setting explicit `account`).
