# PageSift 1.5.0 (Loop)

PageSift 1.5.0 closes the loop across **Sync** (long-lived data sources and incremental resource state), **Adapt** (cross-tick URL family experience and explainable acquisition strategies), and **Evidence** (temporal semantics, independent source roots, claim lifecycles, and point-in-time queries), and exposes these workflows across HTTP, CLI, MCP, Python, Node.js, and C ABI.

---

## What Changed

### 1. Evidence: Temporal Semantics, Source Independence & Claim Lifecycles (`pagesift-graph`, `pagesift-store`)

- **Temporal semantics & `asOf` queries** (`pagesift_graph::temporal`): `DocNode` and `ClaimRecord` carry `TemporalSemantics` (`observed_at_ms`, `published_at`, `modified_at`, `valid_from`, `valid_until`) alongside RFC-3339 / millisecond timestamp parsing via `parse_timestamp_ms`.
- **Source independence deduplication** (`pagesift_graph::independence`): `OriginRelation`, `SourceLineage`, `compute_source_lineage`, and `independent_roots_for_claim_group` (wired into `build_fact_clusters_with_lineage`) distinguish independent corroborating origins from canonical aliases, duplicates, derived artifacts, and citations.
- **Claim lifecycle reconciliation** (`pagesift_graph::lifecycle`): `ClaimStatus` (`Active`, `Superseded`, `Withdrawn`, `Unverified`, `EvidenceDegraded`) and `reconcile_resource_claims` track `Appeared`, `Confirmed`, `Updated`, `Withdrawn`, `Unverified`, and `EvidenceDegraded` claim transitions across versioned observations, avoiding false self-conflicts from superseded values while reconstructing historical state with `claims_as_of`.
- **Persistent claim & point-in-time store queries** (`pagesift-store/src/graph/`): Modularized `GraphStore` (`claims.rs`, `history.rs`, `job.rs`) adds `reconcile_and_store_resource_claims`, `claims_for_resource_as_of`, `list_claims_bounded`, `history_as_of`, and `list_conflicts_as_of` with bounded default limits (`DEFAULT_GRAPH_CLAIMS_LIMIT`, `DEFAULT_GRAPH_HISTORY_LIMIT`, `DEFAULT_GRAPH_CONFLICTS_LIMIT`).

### 2. Adapt: Persistent Family Experience & Explainable Acquisition (`pagesift-plan`, `pagesift-frontier`, `pagesift-engine`)

- **Cross-tick URL family experience** (`pagesift-plan/src/experience.rs`): `FamilyExperienceTable` and `LearnedUrlRule` persist per-family statistics (lightweight HTTP sufficiency, browser escalation gain, conditional 304 hit rate, substantive change rate, claim yield, barrier rate) and falsifiable URL rewrite rules across ticks.
- **Evidence-driven strategy planning** (`pagesift-plan/src/strategy.rs`): Defines `AcquisitionStrategy`, `CaptureAssessment`, `AdaptDecision`, and `CoverageStatus` so extraction sufficiency feeds back into HTTP vs. conditional HTTP vs. browser escalation vs. deferred scheduling with recorded decision reasons.

### 3. Sync: Persistent Data Sources & Monitor Snapshot Offloading (`pagesift-store`, `pagesift-engine`, `pagesift-api`)

- **Persistent Loop sources** (`pagesift-store`, `pagesift-engine`): `DataSourceSpec`, `FreshnessPolicy`, `SyncBudget`, `SyncDelta`, and `SourceStateView` manage resource inventories, bounded deltas (`MAX_DELTAS_PER_SOURCE`), and incremental synchronization ticks via `<Scraper as Engine>::sync_source`.
- **Monitor Markdown offloading** (`crates/pagesift-api/src/monitor/snapshot_ref.rs`): Separates large captured Markdown blobs from monitor JSON state records so monitor state polling stays compact.

### 4. API, CLI, MCP, and Native Language Bindings

- **HTTP API (`pagesift-api`)**:
  - New `/v2/sources` endpoints: `POST /v2/sources`, `GET /v2/sources`, `GET/DELETE /v2/sources/{id}`, `POST /v2/sources/{id}/sync`, `GET /v2/sources/{id}/state`, `GET /v2/sources/{id}/deltas`, and `GET /v2/sources/{id}/deltas/{tick_id}`.
  - New `GET /v2/graph/claims` endpoint and `?asOf=` support on `/v2/graph/history`, `/v2/graph/conflicts`, `/v2/graph/claims`, and `/v2/sources/{id}/state`, backed by shared `store_graph_claims`, `store_graph_conflicts`, and `store_graph_history` helpers.
- **CLI (`pagesift`)**:
  - Added `pagesift sync` subcommands (`init`, `list`, `run`, `status`, `state`, `deltas`, `delete`).
  - Extended `pagesift graph inspect` with `--as-of` historical reconstruction and claim inspection on persisted stores.
- **MCP (`pagesift-mcp`)**:
  - Added `pagesift_sync` tool and extended `pagesift_graph_query` with `claims` and `asOf`.
- **Rust / C ABI / Node.js / Python (`pagesift::loop_ops`, `pagesift-ffi`, `pagesift-node`, `pagesift-py`)**:
  - Added shared `pagesift::loop_ops::{sync, query_graph}` runtime entrypoints.
  - Added `pagesift_sync` and `pagesift_graph_query` to `pagesift-ffi` (`include/pagesift.h`).
  - Added `Scraper.sync` and `Scraper.queryGraph` (`SyncRequest`, `GraphQueryRequest`) to `@pagesift/node` (`pagesift-node`).
  - Added `Scraper.sync`, `Scraper.async_sync`, `Scraper.query_graph`, and `Scraper.aquery_graph` to Python `pagesift` (`pagesift-py`).

## Verification Scope & Notes on Benchmarks

- **Benchmarks**: The full 1.4 offline and live-web benchmark suites (`benchmarks/history/1.4/`) were **not re-run** for `1.5.0`; existing performance figures in the main README continue to reference the `1.4` measurements with their original baseline dates.
- **Loop coverage**: New 1.5.0 Sync/Adapt/Evidence logic, `/v2/sources` and `/v2/graph/claims` routes, `pagesift_sync` and `pagesift_graph_query` MCP tools, `pagesift sync` CLI, and C ABI / Node.js / Python `sync` and `query_graph` bindings are verified by local unit tests, integration tests, and mock local HTTP server round trips rather than multi-week live-web synchronization runs.
