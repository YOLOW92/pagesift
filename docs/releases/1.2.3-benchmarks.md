# Base64 comparison for 1.2.3

Measured on 2026-11-09 on an Intel Core i7-10700, Linux x86-64, CPU 0, Rust 1.99.0 / LLVM 23.1.1. The three implementations were measured in the same process: `pagesift-base64`, Rust `base64` 0.23.1, and `base64-simd` 0.8.0. The latter two were benchmark-only dependencies, not added to the product's runtime dependencies.

Times are **microseconds per call; lower is better**. Release builds used fat LTO and one codegen unit. All implementations reused the same 64-byte-aligned input and preallocated output buffers. Each column is the median of seven alternating rounds, then the median across three full runs; medians in different columns need not come from the same round. Inputs were generated as `(i * 73 + 19) as u8`. Measurements reuse a warm working set and do not establish performance on other CPUs, cold caches or other alignments. Differences of a few nanoseconds are sensitive to noise.

Strict mode uses the standard alphabet with padding. In the CRLF test, CRLF is inserted after every 76 encoded characters, including the final segment. The `base64` comparison includes filtering four whitespace characters into a reused buffer before decoding; `base64-simd` uses `forgiving_decode`. The implementations produce identical bytes for these inputs, but their full whitespace, padding and error semantics differ.

For inputs of 4 KiB and larger, these measurements show lower times for PageSift in all three measured operations against both libraries. Small-input results are mixed: for example, at 8 and 16 bytes PageSift's strict encoding is slower than both alternatives, and at 63 and 64 bytes CRLF decoding is slower than `base64-simd`.
