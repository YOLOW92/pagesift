# PageSift 1.2.6 Release Notes

> **Release Version**: `v1.2.6`
> **License**: AGPL-3.0-only (Commercial licensing available)

Changes since 1.2.5. This release fixes page-quota persistence in single-node deployments. There are no API or configuration changes.

## Failed page reservations are no longer persisted

- **Problem:** 1.2.5 kept one `used` counter that mixed settled pages with in-flight reservations and persisted that counter when any page committed. If two requests reserved a page each and one failed, the other request's commit could write the in-flight page to disk; after a restart the failed page stayed charged for the rest of the UTC day. Concurrent commits could also write snapshots out of order, so an older value could overwrite a newer one and lose settled pages.
- **Fix:** settled usage and in-flight reservations are now separate. Reservations exist only in memory; persistence writes settled usage only. A commit moves the page from the reservation count to the settled count, and writes for the same account are serialized, so a stale snapshot cannot land after a newer one. A reservation that spans UTC midnight is not charged to the new day.
- **Compatibility:** the stored format is unchanged (`day settled`). Values written by 1.2.5 are read as settled usage; a phantom page persisted by a failed request can remain charged until the next UTC day reset. No configuration or API changes.
- **Verification:** `failed_reservation_is_not_persisted` reproduces the restart overcharge on 1.2.5 and passes on 1.2.6; `concurrent_commits_persist_every_settled_page_in_order` reproduces lost committed pages on 1.2.5 and passes on 1.2.6. The API test suite passes.

## Upgrading

No configuration changes. Single-node deployments that use daily page quotas should upgrade. Cluster ledger mode is unaffected.
