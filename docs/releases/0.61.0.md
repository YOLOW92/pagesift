# PageSift 0.61.0 Release Notes

> **Release Version**: `v0.61.0`  
> **Release Date**: October 24, 2026  
> **License**: AGPL-3.0-only (Commercial licensing available)

PageSift 0.61.0 makes same-host batch behavior observable and configurable. It separates admission-queue time from network-fetch time, explains meaningful per-host delays in warnings, and exposes the relevant rate controls through Python's top-level `scrape_many` helper.

## Queue diagnostics

Every scrape now records `metadata.pagesift.timings.queue` in milliseconds. This value covers waiting for global and per-host concurrency slots plus the effective minimum interval between request starts; `metadata.pagesift.timings.fetch` remains the network fetch duration.

When queue time is at least 10 ms, PageSift adds a warning. If `robots.txt` supplied `Crawl-delay`, the warning identifies that policy and reports the effective interval. The same diagnostics are retained for direct browser rendering and HTTP 304 responses.

## Python batch controls

The synchronous top-level helper accepts three new optional keyword arguments:

```python
from pagesift import scrape_many

docs = scrape_many(
    urls,
    concurrency=16,
    max_concurrency=64,
    per_host_concurrency=4,
    request_interval=0.25,
)
```

- `concurrency` controls how many tasks this batch keeps in flight.
- `max_concurrency` controls the scraper's global admission limit.
- `per_host_concurrency` controls simultaneous requests to one host.
- `request_interval` controls the default spacing between request starts; a site-provided `Crawl-delay` still takes precedence.

When any of the three scraper-level controls is supplied, the helper creates a temporary scraper for that batch and closes it afterward. Calls without them continue to use the shared default scraper.

## Auto-render admission fix

An HTTP request upgraded by `engine=auto` previously retained its HTTP admission permit while waiting for a second browser-render admission. A same-host batch could therefore occupy every per-host slot with tasks that were all waiting for another slot. PageSift now releases the HTTP permit before acquiring the browser-render permit, removing that deadlock path.

The default engine remains `auto` for compatibility. In environments without an available browser, callers that know rendering is unnecessary can explicitly choose the HTTP engine and avoid render eligibility checks.

## Compatibility

This release adds optional parameters and metadata without removing existing APIs. Rust workspace crates, `@pagesift/node`, and the dynamically versioned Python package share version `0.61.0`.
