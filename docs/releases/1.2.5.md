# PageSift 1.2.5 Release Notes

> **Release Version**: `v1.2.5`
> **License**: AGPL-3.0-only (Commercial licensing available)

Changes since 1.2.4. This release hardens request credentials and resource limits. Output for valid documents is unchanged.

## Redirect credentials are scoped to the full origin

- **Problem:** a redirect to the same host on a different port (for example `https://example.com:443/` to `https://example.com:8443/`) kept forwarding caller-supplied `Authorization`, `Cookie` and `X-Api-Key` headers. Host and HTTPS-downgrade checks were present; the port was not compared.
- **Fix:** caller-supplied headers are now sent only when the redirect target has the same scheme, host and effective port as the request origin. Conditional headers (`If-None-Match`, `If-Modified-Since`) still follow redirects. Explicit sessions and host-level static credentials keep their existing scoping rules.
- **Behavior change:** a redirect to the same host on another port no longer carries caller credentials. Deployments that relied on that forwarding must configure the target origin separately.

## Page quota is reserved before work starts

- **Problem:** daily page quota was checked, the page was fetched, and only then was the page charged. Concurrent requests could all pass the check and overrun the quota.
- **Fix:** every billable page fetch now acquires an atomic reservation before the request is sent, settles it when the page is delivered, and releases it when the page is not delivered. This covers scrape, parse, interact, locate, search, extract, Jina Reader (plain and SSE), Jina search, crawl, batch, monitor and agent paths. Retries reuse the same reservation instead of charging twice.
- **Failure and cancellation:** errors, robots refusals, duplicate pages, client disconnects, cancellation and crawls stopped by a limit or an exhausted quota release the reservation. A process crash drops in-memory reservations; with the cluster ledger, an unsettled reservation stays frozen for the current UTC day and counts at most the pages in flight at the time of the crash.
- **Compatibility:** billing rules per endpoint are unchanged. A crawl or batch stopped by the quota now reports `QUOTA_EXCEEDED` before the refused page is fetched instead of fetching it first.

## ZIP stored entries are validated before copying

- **Problem:** for stored (uncompressed) ZIP entries the decoder copied bytes using the central directory's compressed size and only then checked the uncompressed size, so a small declared size could drive a large copy.
- **Fix:** stored entries are rejected before the copy when compressed size, uncompressed size and the actual data slice disagree. Offset and size arithmetic is checked.

## MOBI decompression is budgeted per write

- **Problem:** PalmDOC records were decoded in full and the text limit was checked after each record; HUFF/CDIC recursive expansions and cached phrases were only bounded by the final text size.
- **Fix:** PalmDOC checks the remaining budget before every literal, back-reference and character write. HUFF/CDIC checks the budget before every phrase copy and counts recursive expansion buffers and cached phrases against the limit.

## PDF predictor and filter limits (synced with yolowpdf 0.1.1)

- **Problem:** PNG/TIFF predictor row buffers were allocated from untrusted `Columns`, `Colors` and `BitsPerComponent` values before the decode limit was applied. ASCII85, ASCIIHex, RunLength and Crypt paths could allocate or grow output before the limit check.
- **Fix:** the predictor carries the decode budget, validates field arithmetic and rejects row buffers and the TIFF component table before allocation. Each filter checks the limit before reserving, extending or resizing, and returns `TooLarge` instead of truncating.
- **Cross-repository change:** the same PDF fix was implemented in [yolowpdf](https://github.com/YOLOW92/yolowpdf) 0.1.1 (`3da09ad`, `8e1fbe2`) and synced here. The two `filter.rs` files are byte-identical.
- **Compatibility:** valid predictor samples (PNG filters 0–4, TIFF 1/2/4/8/16-bit) decode to the same bytes as 1.2.4. Corrupt inputs that previously parsed by accident may now return a format or size error.

## Upgrading

No configuration changes are required. The redirect credential boundary, quota timing and corrupt-input error behavior above are the only observable changes.
