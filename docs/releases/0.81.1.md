# PageSift 0.81.1 Release Notes: Adaptive Browser Upgrades

> **Release Version**: `v0.81.1`
> **Release Date**: 2026-10-29
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.81.1 makes `engine: auto` browser upgrades self-limiting. The HTTP result is already a valid
document; a browser upgrade is only worth its cost when it produces more main content. The old
path could spend 5–18 seconds on a JavaScript shell, an anti-bot challenge or a page that never
hydrates, even when the browser would return the same text as HTTP.

The new path learns from the pages it actually renders and stops when the extracted content stops
improving. There are no fixed early-stop seconds or fixed render budgets:

- **Online distributions.** Navigation time, settle time, first content time and useful render
  time are tracked as running mean/variance. A bound is used only after the mean standard error is
  small relative to the mean; cold starts keep the existing timeout instead of guessing.
- **Content probe, not `innerText`.** When a page is stable (or after the learned probe time), the
  current DOM is captured and run through the same main-content extractor as the final result. If
  the extracted text is not better than the HTTP result, the browser is stopped and the HTTP
  document is kept. Navigation bars, cookie banners and ad text no longer look like a gain.
- **Hardware-relative patience.** With no cross-page history (for example one `pagesift scrape`
  process per URL), navigation patience scales with the time this page needed to acquire a browser
  tab; a bare client-side redirect scales with its own HTTP fetch time. A busy machine gets more
  patience, not a fixed number of seconds.
- **HTTP-empty pages are protected.** When HTTP extracted nothing, rendering is the only source of
  content, so the local navigation cap is disabled; full browsers still get the time they need.
  Lightpanda is skipped for bare redirect pages, where only a full browser can follow the script.

## Measurements

Local A2 replay, same 269 pages and same per-URL process model as the 0.81 report:

| Configuration | 1 worker | 16 workers |
|---|---:|---:|
| 0.81.0 | 119.2 s / 2.3 pages/s | 28.4 s / 9.5 pages/s |
| 0.81.1 | **77.3 s / 3.5 pages/s** | **10.5 s / 25.7 pages/s** |

Extracted text over the 269 pages: 2,376,184 → 2,375,883 characters (−301, one challenge page that
returned no content through HTTP either). The slowest page fell from 18.2 s to 8.2 s.

On a 24-page A3 (JavaScript-rendered live pages) A/B against the 0.81.0 binary, completion was
0.875 vs 0.792 and reference-word recall 0.389 vs 0.291. Live sites vary between runs; this is a
small sample, not a replacement for the full A3 report.

## Behaviour changes

- `engine: auto` may now return the HTTP document when a browser upgrade does not improve the
  extracted main content, with `render_no_gain_http_fallback` in `warnings`.
- A browser upgrade that exceeds the learned budget or the page's navigation patience falls back
  to the HTTP document with `render_timeout_http_fallback` / `render_failed_http_fallback`.
- Explicit `engine: browser` is unchanged: it still uses the full render timeout and is not
  early-stopped.
