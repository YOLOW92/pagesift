# PageSift 0.80.1 Release Notes: Fixes From the 0.80 Review

> **Release Version**: `v0.80.1`
> **Release Date**: 2026-10-28
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.80.1 fixes what the review of 0.80.0 found. HTML extraction is untouched (pagesift-content
is not changed); PDF output changes only where a raised footnote marker follows a word; speed is
within 1% of 0.80.0 measured against a 0.80.0 baseline on the same machine (see Performance):

- **CSV character sets.** A CSV in Shift_JIS or GBK, or served with `Content-Type: text/csv;
  charset=…`, came out as mojibake with no warning. CSV is now decoded exactly like HTML.
- **Damaged PDFs say what they lost.** A truncated PDF returned the pages it could recover and
  nothing else: no warning, `totalPages` equal to the pages found. Two warnings now describe the
  repair: `pdf_repaired` and `pages_missing`.
- **Footnote markers are not formulas.** `Ashish $Vaswani^{\ast}$` is `Ashish Vaswani*` again.
- **PDF titles.** A PDF without an embedded `/Title` gets the title inferred from the layout in
  `metadata.title`, marked `titleSource: "inferred"`.
- **IPv4-only machines.** `*.localhost` resolves to loopback without a DNS lookup; the test suite
  and the `crawl_gate` performance gate no longer need `::1`.
- **Third-party notices travel with the binaries.** `NOTICE` names Adobe cmap-resources and is
  packaged into the release archives, the Docker image, the npm packages and the Python wheels.
- **Correction to the 0.80.0 notes.** `POST /v2/parse` accepts Word, Excel, PowerPoint, EPUB and
  CSV as well as PDF and HTML.

Reproduction and verification for every fix below were done on a Linux x86_64 container (4 cores,
no IPv6) with the 0.80.0 and 0.80.1 release builds of this repository. The real arXiv paper named
in the review (1706.03762) could not be downloaded from that container (outbound access to
arxiv.org is refused there), so the PDF fixes are **covered by local test cases only**: PDFs
generated in code that reproduce the structure the review described (a CMSY-font asterisk raised
after a Helvetica name; a file without `/Info /Title`; a file truncated inside its last page
object). No claim below about those PDFs has been checked on the real arXiv file.

## CSV character sets (review item D-1)

**Before.** `pagesift-office` decoded CSV on its own: a BOM, else valid UTF-8, else Windows-1252.
The HTTP `Content-Type` never reached it, so `charset=shift_jis` was ignored, and a Shift_JIS or
GBK file was mapped byte-by-byte through Windows-1252. Reproduced on 0.80.0 with a Shift_JIS table
uploaded to `/v2/parse` as `text/csv; charset=shift_jis`: the header row came back as
`| ”Ô† | “sŽs | ”—Ê | ”õl |` and `metadata.pagesift` had no `warnings`.

**Now.** The engine decodes CSV with the same function as HTML responses (`pagesift_net::decode`):
BOM, then the `charset` parameter of the response or upload Content-Type, then body detection
(chardetng plus the statistical detector), and a declaration that contradicts the body is
corrected with a `decode:` warning, exactly as for pages. `pagesift-office` gained
`convert_csv_text` for text that is already decoded; its own `convert` keeps the old fallback for
library users without a Content-Type. The same Shift_JIS upload now gives `| 番号 | 都市 | 数量 | 備考 |`.

Local test cases (`crates/pagesift/tests/office.rs`): a Shift_JIS file served with its charset;
a GBK file served as plain `text/csv` (detected from the body); a GBK file served as
`charset=utf-8` (corrected, with the `decode:` warning); the same files uploaded to `/v2/parse`.

## Damaged PDFs: `pdf_repaired` and `pages_missing` (review item D-2)

**Before.** When the cross-reference table is unusable, pagesift-pdf rebuilds the object index by
scanning the file (0.80.0's own file layer). Page objects that the page tree references but the
file no longer contains were skipped silently, and `metadata.page_count` was the number of pages
found. Reproduced on 0.80.0 with a 3-page file cut inside the third page's object: 200 OK,
`numPages: 2`, `totalPages: 2`, no warnings, while the file's `/Pages /Count` says 3.

**Now.** The file layer records whether it opened in repair mode (or had to locate objects by
scanning because the table's offsets were wrong), reads `/Count` from the root page node, and
counts page-tree children whose object is missing or only half present. pagesift-pdf returns these
as `PdfDocument::warnings`, and the engine adds them to `metadata.pagesift.warnings`:

- `pdf_repaired: the cross-reference table was unusable; objects were recovered by scanning the file`
  (or `… some cross-reference offsets were wrong; objects were located by scanning the file`).
- `pages_missing: 2 of 5 pages could not be recovered from the damaged file; 3 converted`.

`numPages` and `totalPages` stay the pages that were actually recovered (what `pages` contains);
the warning carries the declared total. The audit log counts `pages_missing` as a suspicious
result and keeps a snapshot; the CLI prints it on stderr. An intact file gets neither warning, and
a file whose `/Count` merely over-reports (no object missing) gets none either.

Local test cases: a 5-page hand-written PDF truncated inside page 4 (`crates/pagesift-pdf/tests/
extract.rs`: 3 pages recovered, both warnings, `page_count 3`); the 3-page file above through
`/v2/parse` (`crates/pagesift/tests/parse.rs`).

## Footnote markers after names (review item S-3)

**Before.** In LaTeX output the `*`, `†`, `‡` after an author's name come from a math font
(CMSY's `∗` is U+2217), so the word `Vaswani∗` was classified as mathematics and written as
`$Vaswani^{\ast}$`. Reproduced on 0.80.0 with a generated 40-page paper whose author line uses
Helvetica names and 8 pt CMSY10 asterisks raised 3.6 pt: the first heading line came out as
`## Ashish $Vaswani^{\ast}$`, the same shape the review quoted from the real paper.

**Now.** A word made of text-font letters with a trailing raised marker (`∗ * † ‡ § ¶ ‖` or
digits), or a lone raised marker symbol right after a text word, is a footnote reference, not a
formula: it stays text, and the math-font `∗` is written as a plain `*`. The decision uses the same
size and baseline thresholds as superscript detection, so the same symbols on the baseline
(`x ∗ y`), or raised after a math-font variable (`f^{\ast}`), or a lone raised digit (an exponent)
are still formulas. The generated paper now gives `## Ashish Vaswani* Noam Shazeer* …` and
contains no `\ast`.

Local test cases: `crates/pagesift-pdf/src/math/mod.rs` (the author line, and the three cases that
must stay math) and `crates/pagesift-pdf/tests/extract.rs` (a generated PDF with a CMSY10 font).

## PDF titles (review item S-4)

**Before.** `metadata.title` was the `/Info /Title` only. A PDF without one (the review's arXiv
file has neither `/Title` nor XMP) had no `title` even though the Markdown started with
`# Attention Is All You Need`. Reproduced on 0.80.0 with a generated file without `/Title`.

**Now.** pagesift-pdf also returns `inferred_title`: the first top-level heading of the first page,
whether it came from the structure tree, the bookmarks or the layout inference. The engine uses
it when `/Info` has no title and marks the result with `metadata.titleSource: "inferred"`; a file
with its own title is unchanged and has no `titleSource` field.

Local test cases: `crates/pagesift-pdf/tests/extract.rs` and `crates/pagesift/tests/parse.rs`.

## IPv4-only machines

Reported by the maintainer while setting up a container without IPv6: `cargo test --workspace`
failed in `tests/multihost.rs` with `Address family not supported by protocol`, and the
`crawl_gate` performance gate that `scripts/ci.sh` runs failed the same way. Both bound their
local origin to `[::1]`. A second cause sits in the product: pagesift handed `a.root.localhost`
to the system resolver, and a resolver without systemd-resolved or the glibc `myhostname`
module (`hosts: files dns`, common in containers and on servers) does not resolve subdomains of
`localhost` at all.

`localhost` and `*.localhost` now resolve to `127.0.0.1` and `::1` without a lookup, as RFC 6761
§6.3 asks; the SSRF policy still applies to the result. The test and the gate serve on
`127.0.0.1`. Verified on the container above: the multi-host test passes, and `crawl_gate` runs
(it could not run on 0.80.0 there). The benchmark origin servers under `benchmarks/crawl` still
bind `::1`; they are the maintainer's measurement tools and were left alone.

## Third-party notices (review item S-2)

The CID-to-Unicode tables that decode CJK text in PDFs without `ToUnicode` (new in 0.80.0) are
generated from Adobe cmap-resources, BSD-3-Clause. The license was in the source tree
(`crates/pagesift-pdf/src/font/cid2uni/LICENSE-Adobe.md`) but the root `NOTICE` did not name it,
and the release archives contained no `NOTICE` at all. BSD-3-Clause requires the notice in the
documentation or other materials of a binary distribution.

`NOTICE` now has the attribution and the full license text. The release workflow copies `NOTICE`
into the binary archives, the Docker image (`/usr/share/doc/pagesift/`), the main and platform npm
packages and the Python wheels and sdist, together with `LICENSE`. These are changes to
`.github/workflows/release.yml` and the `Dockerfile`; they take effect on the first release built
with them, so the v0.80.1 archives are the first to be checked.

## Correction to the 0.80.0 release notes (review item S-1)

The 0.80.0 notes and CHANGELOG described `POST /v2/parse` as an upload endpoint for PDF and HTML.
0.80.0 also shipped `pagesift-office`: `/v2/parse` and `/v2/scrape` convert Word (`.docx`), Excel
(`.xlsx`), PowerPoint (`.pptx`), EPUB and CSV as well, as `docs/parse-api.md` and the README
already said. The published 0.80.0 notes are not rewritten (see [docs/releasing.md](../releasing.md));
this entry is the correction.

## Performance

Same machine, same fixtures, 0.80.0 and 0.80.1 release builds built from this repository; the
instruction counts are from `valgrind --tool=callgrind` and do not depend on load. Lower is better
in every column. The fixtures are synthetic and generated in code (no network): the 40-page paper
described above, a 5 MB ASCII CSV, a UTF-8 CJK CSV, and the Shift_JIS and GBK CSVs. The two
legacy-charset CSVs are listed for completeness but are not comparable across versions: 0.80.0
decoded them wrongly (Windows-1252) and produced different output.

| Fixture | Measure | 0.80.0 | 0.80.1 | Change |
| --- | --- | ---: | ---: | ---: |
| 40-page paper (PDF) | instructions, 3 extractions | 2,194,527,360 | 2,207,402,868 | +0.59% |
| 40-page paper (PDF) | best of 7, ms | 91.5 | 91.1 | −0.4% |
| ascii.csv, 5.1 MB | instructions, 3 conversions | 4,296,566,432 | 4,318,530,413 | +0.51% |
| ascii.csv | median of 7, ms | 151.6 | 136.9 | −9.7% (noise; same code path) |
| utf8-cjk.csv, 1.3 MB | instructions, 3 conversions | 1,176,671,975 | 1,182,424,119 | +0.49% |
| utf8-cjk.csv | median of 7, ms | 37.1 | 39.2 | +5.8% (noise; instructions +0.49%) |
| sjis.csv, 1.2 MB | instructions, 3 conversions | 1,586,495,037 | 1,625,363,985 | not comparable: 0.80.0 output was mojibake |
| gbk.csv, 1.1 MB | instructions, 3 conversions | 1,459,031,365 | 1,794,052,640 | not comparable: 0.80.0 output was mojibake |
| `perf_gate` blog 100 KB (HTML) | median ms | 6.12 | 6.31 | pagesift-content unchanged; binary identical |
| `perf_gate` wiki 250 KB (HTML) | median ms | 28.36 | 27.69 | pagesift-content unchanged; binary identical |
| `crawl_gate`, 1,200 pages | pages/s, 3 runs | 578–633 | 646–701 | 0.80.0 needed a hosts-file workaround to run at all |

The PDF path pays 0.59% more instructions for the footnote check on every line that contains a
math-font glyph, the page-tree accounting and the title scan. The CSV path for UTF-8 input pays
0.5% for the NUL scan and the Content-Type check; the decoder that follows is the same copy as
before. The legacy-charset CSVs now go through chardetng on a 64 KiB sample and one full decode;
the first version of this fix detected on the whole body and cost 3.6× (Shift_JIS) and 7× (GBK)
the instructions of 0.80.0, which is why detection is sampled.

`crawl_gate`'s floor of 1,500 pages/s was set on an i7-10700; this 4-vCPU container reaches
580–700 pages/s on either version, so the absolute floor is not meaningful here. The comparison
is: the loopback change does not slow the crawler (0.80.1 runs 646–701 pages/s against 578–633
for 0.80.0, which could only run here with `s0.localhost` … `s19.localhost` added to
`/etc/hosts`; 0.80.1 no longer needs that).

The fixture generator, the measurement script, the raw results and the reproduction record are in
[benchmarks/history/0.80.1/](../../benchmarks/history/0.80.1/README.md).

## Upgrading

No configuration changes. New fields and warnings are additive: `metadata.titleSource`,
`pdf_repaired`, `pages_missing`, the `decode:` warning on CSV. Library users of pagesift-pdf get
two new fields on `PdfDocument` (`inferred_title`, `warnings`); `pagesift-office` and `pagesift`
gain `convert_csv_text` and `office_markdown_from` and keep the old functions.
