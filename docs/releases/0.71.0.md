# PageSift 0.71.0 Release Notes: Honest Failure Reporting and Safer Crawling

> **Release Version**: `v0.71.0`
> **Release Date**: 2026-10-26
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.71.0 is a bug-fix release for issues found in the 0.70.0 field audit. It does not change the
extraction engine or the public response contract. The focus is on making failures visible and
making authorization apply consistently:

- crawls that start from a file URL now cover the whole site;
- local files and network responses use the same charset logic;
- `NO_PROXY` and `--allow-cidr` are honored on every path;
- binary, empty and captcha responses are no longer reported as ordinary success;
- TLS certificate failures have their own machine-readable error codes;
- browser authorization matches HTTP authorization;
- root/sandbox and auto-fallback failures explain themselves;
- CLI exit codes distinguish a failed request from an HTTP error page;
- framework-hidden templates no longer leak into Markdown;
- piping CLI output into `head` or another early-closing reader no longer panics.

All ten audit items are fixed and covered by regression tests. Performance is unchanged within
measurement noise; peak RSS grew by 1.6–4.1% (below the 5% release gate).

## Fixes

### Crawl scope

`crawl https://example.com/index.html` now scopes the crawl to the containing directory instead
of treating `index.html/` as the prefix. A seed whose links are all filtered emits a
`crawl_followed_zero` warning instead of silently returning one page.

### Charset handling

`convert` now uses the same BOM → meta prescan → detection pipeline as network fetching, and
accepts `--charset` for explicit overrides. BOM, `meta charset`, legacy `http-equiv`, Shift_JIS,
EUC-JP, GBK, Big5, windows-1251 and KOI8-R are covered.

### Proxy and allow-list semantics

`NO_PROXY` / `no_proxy` are honored for environment proxies. Targets admitted by
`--allow-cidr`, `allow_hosts` or `allow_ips` connect directly. Named egress proxies still keep
their explicit proxy semantics and are not bypassed by allow-lists.

### Honest content reporting

- Image, audio, video, font and archive responses return `UNSUPPORTED_OPTION` instead of being
  decoded as text. HTML mislabeled as `application/octet-stream` is still accepted.
- HTTP < 400 responses with no extractable text carry an `empty_content` warning.
- bilibili captcha pages return `ACCESS_BARRIER` with vendor `bilibili`.

### Browser authorization

Browser sub-requests consume the same `allow_hosts` / `allow_ips` / `allow_cidrs` list as HTTP
fetching. Chrome uses the CDP allow-list guard; Lightpanda receives matching `--block-cidrs`
exemptions. A browser request without an allow-list is still blocked from private networks.

### TLS classification

Certificate failures are no longer folded into `NETWORK_ERROR`:

| Error code | Meaning |
| :--- | :--- |
| `TLS_CERT_EXPIRED` | certificate expired or not yet valid |
| `TLS_HOSTNAME_MISMATCH` | certificate does not cover the requested host |
| `TLS_UNTRUSTED_ROOT` | chain not trusted (self-signed, missing issuer) |
| `TLS_ERROR` | other TLS handshake/certificate error |

Classification works on direct connections, CONNECT proxies, reqwest-based proxied transfers and
Chrome navigation errors (`ERR_CERT_*`). Certificate failures are deterministic failures and do
not enter network-jitter backoff.

### Root diagnostics and auto fallback

`pagesift doctor` reports the browser as `FAIL` when running as root and explains the Chrome
sandbox constraint. `scrape --engine browser` reports the launch failure reason instead of
"no browser engine found". `--engine auto` prints the downgrade reason in CLI Markdown mode and
keeps `render_unavailable` in `metadata.pagesift.warnings`.

### CLI exit codes

| Situation | Exit code | Warning |
| :--- | ---: | :--- |
| HTTP < 500 with content | 0 | — |
| HTTP 404 with empty content | 2 | `http_error_status: HTTP 404` |
| HTTP >= 500 | 2 | `http_error_status: HTTP 500` |
| robots/barrier/network/request failure | 1 | error code |

The JSON body keeps `success=true` for fetched error pages so the Firecrawl-compatible contract
is unchanged; the CLI exit code and warning make the page status visible to scripts.

### Hidden templates

Elements marked `x-cloak`, `data-cloak`, `v-cloak` or `ng-cloak` are treated as pre-hydration
templates and filtered. App shells containing `main`, `article` or `role=main` are preserved.
Plain `display:none`, `hidden`, `template` and `aria-hidden` behavior is unchanged.

### CLI pipes

`pagesift doctor | head -1` and similar pipelines now exit with the conventional SIGPIPE status
141 instead of printing a Rust panic and exiting 101. Stdout and stderr writes detect
`BrokenPipe` and stop quietly; the network stack is unchanged.

## Known limits

- moli does not accept negative CIDR exemptions; fine-grained `--allow-cidr` still cannot pass
  its kernel-level `--block-private-networks` guard. Chrome and Lightpanda are covered.
- Browser DNS rebinding remains the same risk as the existing `PrivateNetworkGuard`; CIDR checks
  use the local resolution result.
- Only framework/CSS-hidden templates are filtered. Visible server-rendered i18n text remains
  page content and is not removed heuristically.

## Upgrade

No configuration or API changes are required.

```bash
docker pull ghcr.io/yolow92/pagesift:0.71.0
```

CLI scripts that treat any non-zero exit code as failure should account for exit code 2
("page fetched, HTTP status is an error") if they intentionally fetch 404/5xx pages.
