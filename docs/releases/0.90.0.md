# PageSift 0.90.0 Release Notes: Measured Instead of Fixed

> **Release Version**: `v0.90.0`
> **Release Date**: 2026-11-03
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

Most limits, timeouts and thresholds that earlier versions hard-coded are now estimated from what the
process observes. The old value is the starting point: with no observations the behaviour is the 0.81.5
behaviour, and an estimate replaces it only when the difference is statistically significant (δ = 0.05).
User settings, safety limits and protocol values stay hard limits.

Also new: render decisions per path family with an `explain` trace, binary cache, `--out` / `--warc`
outputs, crawl and batch streams, a structure-aware RAG chunker, PDF page quality checks and image export,
an egress pool, and multi-server roles (`gateway`, `worker`, `standby`).

On the local comparison set (1,834 pages, 2,204 requests), 2,150 responses are byte-identical to 0.81.5.
The other 54 differ only in headings: 26 use the page's `<h1>` as the title line instead of `<title>`,
27 keep headings that 0.81.5 removed, and 1 adds a heading to `html` only. No body paragraph differs.

**Behaviour changes to know about when upgrading:**

- `--tuning-mode` is accepted and ignored. `diagnose` / `tune` report the hardware, the memory budget and
  the starting values instead of tuning tiers.
- Removed from `pagesift-net`'s public API: `scheduler` (`WorkerPool`, `DomainLimiter`, `RingQueue`),
  `checkpoint` (`RecoveryEngine`, `TaskSnapshot`), `budget` and `ChunkFetcher`. pagesift used none of them.
  Removed from `pagesift-policy`: the `adaptive` module (topology detection moved to `topology`).
- Cache entries written by 0.81 are not read (new binary cache format). They expire as usual.
- Every crawl reports a summary (`stopReason`). The CLI writes `summary.json` for every crawl with `--out`.
- The rate-limit queue warning appears only when politeness pacing (request interval, Crawl-delay) made a
  request wait longer than the fetch itself.
- PDF parsing has a size-based time limit instead of 30 s. Scanned pages are marked in the Markdown.
- `{"type":"recursive"}` chunking merges by block structure; chunk boundaries differ from 0.81.
- With an egress pool configured, the browser uses the chosen egress for every request, loopback included.
- `[cluster] weight` is removed; a worker's weight is its admitted concurrency.

## Execution

- **CPU worker pool:** one resident worker per core, grouped by NUMA node, with work stealing inside the
  node first.
- **Decompression:** moves to a worker only when the expected time exceeds a measured cross-thread round
  trip.
- **DOM:** one DOM per HTTP page.
- **Cache:** I/O runs on workers, not on the async threads.
- **Audit log:** written by its own writer thread.

Speed on the local 1,834-page set, 0.81.5 and 0.90.0 interleaved in the same session (`benchmarks/history/0.84/speed.sh`):
single-request p50 3.96 ms → 3.99 ms (lower is better); 16 concurrent requests, median of 9 rounds over two runs,
792 → 839 pages/s (higher is better). Results: `benchmarks/history/0.84/results/speed-20261103-132110` and
`speed-stages-20261103-1325`.

## Inputs and outputs

- **Metadata keys:** one mapping, `pagesift_sink::meta`, used by the HTTP API, MCP, CLI, Python and Node.
- **Cache:** self-describing binary format. It keeps link anchor texts and hreflang alternates.
- **CLI output:** `--out` and `--warc` (WARC/1.1) for `scrape`, `crawl` and `convert`.
- **Crawl and batch streams:** `GET /v2/crawl/{id}/stream` and `/v2/batch/scrape/{id}/stream` stream as
  SSE or NDJSON, resume with `cursor` or `Last-Event-ID`, and send keepalives.
- **Webhooks:** events carry `eventId` and `seq` and go through a durable queue that resumes after a
  restart.
- **Jina reader SSE:** frames are written as soon as they exist.

## Limits and timeouts from data

See `docs/history/0.86_fixed_values.md` for every replaced value. In short:

- **Concurrency:**
  - Global concurrency follows a Universal Scalability Law fit.
  - Per-host concurrency follows a latency gradient over concurrency levels. It drops one level at once
    when latency reaches 1.5 × the unqueued latency (the 0.81 rule).
- **Network:** stage timeouts use Kaplan–Meier survival; DNS caching uses the record TTL.
- **Backoff:** outage-based, never shorter than the 0.81 backoff when politeness is on.
- **Browser:**
  - Render and launch limits move down only on significant evidence.
  - Browser memory is measured (PSS) instead of taken from a table.
  - Tab slots go through the unified admission.
  - The browser sends the same `Accept-Language` as HTTP fetches.
- **Office conversion:** the time limit follows input size after 59 conversions.
- **Crawl retries:** retries follow the per-class retry success rate.
- **Focus link scoring:** online logistic regression with the 0.81 weights as the prior.

## Render decisions

- **Render or not:** inside the 0.81 candidate gate, each path family learns whether rendering helped
  (Thompson sampling on a Beta count).
- **Which result to keep:** rendered or merged results are kept when they carry more weighted text (the
  0.81 rule) or score higher on the calibrated quality score.
- **Page data islands:** text from `__NEXT_DATA__`, `__NUXT_DATA__` and `application/ld+json` is merged
  into the HTTP result when it adds blocks and raises the score.
- **Engine fallback and starting engine:** both are learned per family and per site.
- **Speculative rendering:** when a family's learned render probability makes it worth it and browser
  slots are free, the browser starts as soon as the HTTP body arrives instead of after extraction.
- **Trace:** `"explain": true` (CLI `scrape --explain`) writes each decision to
  `metadata.pagesift.plan.steps`.

## Content

- **RAG chunking:** `{"type":"recursive"}` keeps whole blocks within the budget and merges them by
  structure. Recall is significantly higher in all three cells with chunk budget 400 (higher is better).
- **PDF:**
  - Per-page quality scores; low-scoring pages are rechecked through another text path.
  - Button captions are read.
  - Time limit from a size regression (leave-one-set-out: 0 false kills).
  - Results: B3 completion 0.64 → 0.72 (+0.08 [+0.03, +0.14]).
- **Images:**
  - PDF image records with page and position.
  - Scanned pages marked in the Markdown.
  - Export in the original encoding (JPEG, JPEG 2000, CCITT as TIFF, JBIG2, lossless as PNG).
  - Office and EPUB media listing.
  - Delivered everywhere with `exportImages`: `images/<hash>.<ext>` under `--out` with local Markdown
    links, attachments with a download endpoint in the HTTP API, resource links in MCP, bytes in Python
    and Node.
- **Main content:**
  - Headings whose anchor id is their own text are no longer removed.
  - Headings that link to their own section are no longer treated as link blocks.
  - A matching `<h1>` is preferred to `<title>`.

## Multiple servers

- **Roles:** `pagesift serve --role gateway|worker|standby` with a `[cluster]` section.
- **Gateway:** owns the crawl frontier, deduplication and quotas, and sends pages to workers by weighted
  rendezvous hashing on the site.
- **Leases:** fencing tokens and idempotent commits, so a killed worker's pages are redone elsewhere
  without duplicates.
- **Gateway concurrency:** the sum of the online workers' admitted concurrency.
- **Warm standby:** replays the gateway's journal (ledger, job records, webhook queue) and takes over with
  a higher term. `/v2/crawl/{id}` keeps answering and unfinished jobs continue.
- **MCP through the gateway:** available with `[cluster] mcp_port`.

## Egress pool

- **Configuration:** `[[egress]]` entries take a `class` (datacenter, residential, mobile, direct).
- **Selection:** with two or more egresses, each site learns which egress gets denied, by Thompson
  sampling with shrinkage site → registered domain → class.
- **Rate limiting:** only backs off; it never switches egress.
- **Browser:** uses the chosen egress through a per-context proxy.
- **Audit:** requests that ignore robots.txt are written to the audit log (`robotsIgnored`).
