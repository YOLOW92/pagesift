# PageSift 0.80.9 Release Notes: Closing Out 0.80

> **Release Version**: `v0.80.9`
> **Release Date**: 2026-10-28
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.80.9 is the last release of the 0.80 line. It answers the thirteenth round of outside testing
(engines that are installed but not found, and `doctor` reporting a dead engine as healthy),
checks focused crawling on many more universities and in five directions instead of one, works on
the weak spots that the mixed benchmark of 2026-10-27 listed, and fixes four problems found in code
review. Every change is a general rule, not a case written for one site or one file, and the
instruction counts of every benchmark stay within 2% of 0.80.0.

0.80.6, 0.80.7 and 0.80.8 were not released: everything since 0.80.5 is in this one.

**Behaviour changes to know about when upgrading:**

- `pagesift doctor` starts every engine once; an engine that is installed but cannot start is
  reported (`WARN`, or `FAIL` when none starts), so a run that used to say "ok" may now warn.
- In a focused crawl (`--query`), a page whose text is identical to one already delivered (the
  same page under another URL) is no longer delivered and no longer counts against `limit`.
- PDF output now includes the text of annotation appearances: filled-in form fields, FreeText
  notes, stamps and signature blocks.
- The Office/EPUB/CSV output budget (16 MB by default) is a hard limit on the final Markdown.

## Engines and doctor

- **Finding engines outside `PATH`.** Discovery already read `PATH`, but `sudo` (its
  `secure_path`), systemd units and cron often start pagesift with a reduced one. Engines are now
  also looked for in `~/.local/bin`, `~/bin`, `/usr/local/bin`, `/usr/bin` and
  `/opt/homebrew/bin`; Lightpanda is found under its release file names
  (`lightpanda-x86_64-linux` …); and the newest Chromium in Playwright's browser cache
  (`$PLAYWRIGHT_BROWSERS_PATH` or the default cache) is used when nothing else is installed.
- **`doctor` starts each engine.** Before, `doctor` only checked that each engine's file existed,
  so a Chrome that crashed on launch was listed as healthy and the fallback chain looked complete.
  Now each engine is started once: `FAIL` when none starts, `WARN` when some cannot, with what it
  means (pages are rendered by a later engine instead, or pages the earlier engines cannot render
  get no fallback).

## robots.txt on the command line

`crawl` and `map` gain `--ignore-robots`. Only single-page `scrape` had the flag; a crawl could
ignore robots.txt only through the HTTP API, which in turn needs the operator's
`allow_crawl_ignore_robots = true`. On the command line the person running pagesift is the
operator, so the flag is the permission. The HTTP API rule is unchanged.

## Focused crawling, checked wider

The 0.80.3 check used 38 universities and one query (international admission). This release used
69 universities (31 new: mainland China, Hong Kong, Taiwan, Japan, Korea, India, Saudi Arabia,
South Africa, Latin America, the Nordics, continental Europe, Australia, the US) and five
directions: international students, graduate admission, housing, the computer science department,
and the library. robots.txt was ignored so that every version sees the same pages.

| Version | Pages | On the query (U) | On or near it (U+M) | Sites with no U page |
| :--- | ---: | ---: | ---: | ---: |
| 0.80.0 | 3,572 | 2.6% | 18.4% | 266 of 309 |
| 0.80.9 | 3,421 | 19.0% | 49.6% | 116 of 309 |

Per direction (U+M): international 27% → 63%, graduate 26% → 56%, housing 7% → 21%, computer
science 30% → 67%, library 2% → 40%.

Studying the failures pointed to two general problems, both fixed:

- **Stale scores.** Term weights are learned from the pages fetched so far ("research" and
  "students" are on every university page and stop counting), but a queued link kept the score
  it got when it was found. The first links from the home page, scored before any weights
  existed, stayed ahead of better links found later. Each queued link now keeps what its score
  was made of, and the whole queue is re-scored when the weights move by more than 0.05.
- **One page under several URLs.** Links that differ only in a tracking parameter
  (`?ucam-ref=home-menu`, `?ucam-ref=global-footer` …) were each fetched and delivered, using up
  the page budget. A page whose text matches one already delivered is now skipped without using
  the budget, and the queue applies the parameter rules learned from such duplicates (breadth-first
  crawls already did). Same-path duplicates in the run: 38 → 7.

A third idea, taking the first term weights from the home page's own links, helped housing and
computer science but cost graduate admission 4.5 points (the navigation words that query needs
are the common ones) and was not shipped. Raw results and the grading script:
[`benchmarks/history/0.80.9/`](../../benchmarks/history/0.80.9/).

## Mixed-benchmark weak spots

The [mixed benchmark](../../benchmarks/mix/results/report-2026-10-27.md) lists where pagesift is
behind. Each was reproduced from the benchmark's public inputs, studied, and fixed where a
general fix exists.

### Hard PDFs (pdf.js test files): 0.56 → 0.61

Of the 44 files that gave no text: 8 need a user password (pdf.js's own test manifest lists the
passwords; no tool opens them), 26 contain no text at all (pdftotext also finds 0 words; the tools
that score here print image placeholders), 10 had their text in **annotation appearances** and 1
used an unusual **Type3 font**.

- Annotation appearances are drawn as viewers draw them: the normal appearance (`/AP /N`, by
  `/AS` for multi-state widgets) of every visible annotation, placed on its `/Rect` (ISO 32000-2
  algorithm 8.1). Only text is taken; field borders and backgrounds would otherwise read as table
  rules. Hidden annotations, links, popups and push buttons ("Submit", "Reset") are skipped.
  Form fields without an appearance (`/NeedAppearances`) contribute their value.
- Type3 fonts with a `FontMatrix` far from the usual 1/1000 (`[1 0 0 -1]` with `0.12 Tf`) were
  sized at a fraction of a point and dropped; the size is now corrected from the glyph widths when
  it is off by more than 4×, and made-up glyph names (`/BT`, `/a12`) fall back to the base encoding.

250 further pdf.js test files and 15 arXiv papers were compared before and after: 18 outputs
changed, all by added text (field values, signatures, notes, and a figure in the GPT-3 paper whose
text used to be dropped). Extraction time is unchanged.

### One process per file: lighter start-up

The benchmark runs `pagesift scrape <file>` once per file. A small PDF parses in 0.07 ms, but the
process spent 9.4 ms of CPU on start-up: a multi-thread runtime with one worker per core, a CPU
topology probe, worker threads pinned to fixed cores (useful for a crawl that owns the machine,
harmful when many short processes run side by side), and the system root certificates parsed once
per HTTP client. `scrape` now uses a single-threaded runtime without probing or pinning (crawl,
map and serve keep theirs), and the root certificates are read once per process, on the first
HTTPS connection; a local file never reads them. CPU per call 6.3 → 4.3 ms; one-process-per-file
throughput +23% with one worker and +44% with four on a 4-core machine.

### Fetching speed: unchanged by design

On 214 random pages, `engine: auto` escalated 55 short pages to a browser, and the browser found
clearly more text for 21 of them. No signal available before rendering separates the two groups,
so the rule stays: skipping it would lose real content to save time. For raw fetch speed, use
`--engine http`.

### Main-content recall on the Firecrawl set

Most of the lines pagesift misses no longer exist on the live pages or are navigation that
pagesift leaves out on purpose. The general gap was accordion and FAQ headers: a `<button>` with
`aria-expanded`/`aria-controls` (the WAI-ARIA disclosure pattern, like `<summary>`) was removed in
article mode, so answers appeared without their questions. Such headers are kept now; short
controls ("Expand all") are still dropped.

## Fixes from review

- **Output budget.** An EPUB chapter was converted and kept whole before the budget was checked
  (one 100 MB chapter passed a 16 MB limit), and CSV counted cell text but not the table's
  separators and escapes. Chapters are now cut to what is left, and every conversion's final
  Markdown is cut at the limit, at a line boundary, with the `output_truncated` warning.
- **Re-publishing a release** from the workflow form built whatever branch was selected; every job
  now checks out the tag's own commit.
- **MSRV.** `scripts/ci.sh` checked Rust 1.88 while `Cargo.toml` says 1.89, and skipped the check
  when the toolchain was missing. It now reads `rust-version`, installs the toolchain if needed and
  also runs in CI; the workspace builds on 1.89.
- **Wall-clock check.** `scripts/check_wall_clock.py` now also covers `#[cfg(test)]` code inside
  ordinary source files.
