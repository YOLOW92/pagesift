# PageSift 0.81.3 Release Notes: Tag Filters and Authenticated Jina Routes

> **Release Version**: `v0.81.3`
> **Release Date**: 2026-10-30
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.81.3 fills one gap in Firecrawl compatibility and closes one gap in the API server's access
control.

- **`includeTags` / `excludeTags` are implemented.** Until now the HTTP API accepted the fields
  without applying them, and the Python SDK rejected them with `UnsupportedOption`.
- **Jina Reader routes are authenticated.** `GET /r/{url}` and `POST /r` were mounted outside the
  API-key middleware, so a server started with `PAGESIFT_API_KEYS` still served them to anyone, and
  they did not count against rate limits or page quotas.

## Tag filters

Each entry is a CSS selector: a tag name (`article`), a class (`.post`), an id (`#main`) or any
other selector the engine supports. Filtering happens on the HTML before main-content extraction.

- `excludeTags`: every matching element is removed together with its subtree.
- `includeTags`: only matching elements are kept in `<body>`, in document order. When matches are
  nested, only the outermost one is written. `<head>` is kept, so title, description and other
  metadata are extracted as before. `excludeTags` still applies inside the kept elements.
- `rawHtml` is the original page; the filters affect only the extracted formats.
- An invalid selector returns `INVALID_REQUEST` naming the field and the selector, before the page
  is fetched. The Python SDK raises `InvalidRequest` for the same case.

```bash
curl -s localhost:3002/v1/scrape -H 'Authorization: Bearer sk-test' -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com","includeTags":["article"],"excludeTags":[".ad","nav"]}'
```

## Jina Reader routes

The `/r/` routes now share the Firecrawl routes' middleware:

- With API keys configured, a request without a valid key gets `401`.
- `GET /r/{url}` counts against the per-minute request limit like a `POST`; status-polling `GET`
  requests still do not.
- Each successful scrape consumes one page of the caller's quota, and a caller over quota is
  refused before fetching.
- Successes and failures are counted in `/metrics`.

Servers started without API keys behave as before.

## Behaviour changes

- Python: `include_tags` / `exclude_tags` no longer raise `UnsupportedOption`.
- HTTP API: requests with `includeTags` / `excludeTags` now return filtered content.
- Jina Reader routes require an API key when keys are configured.
