# PageSift 1.4.0

`2026-11-14`

PageSift `1.4.0` moves the remaining core format, syntax highlighting, and compression codecs into standalone upstream Rust crates (`yolowdoc 0.1.1`, `yolowsyntax 0.1.2`, `yolowzstd 0.1.2`) and introduces **PageSift DataGraph** (`pagesift-graph`) to build structural relationships, provenance, version lineage, field-level evidence, fact clusters, and conflict records across pages and documents.

---

## Standalone `yolow*` Dependencies

`pagesift-office`, `pagesift-syntax`, and `pagesift-compress` now delegate directly to upstream crates published on crates.io, joining `yolow64 0.3.0`, `yolowpdf 0.1.2`, `yolowhtml-dom 0.1.0`, and `yolowhtml 0.1.0`:

| PageSift crate | Upstream crate | Role |
|---|---|---|
| `pagesift-office` | `yolowdoc 0.1.1` | Office (`.docx`, `.doc`, `.xlsx`, `.xlsb`, `.xls`, `.pptx`, `.ppt`, OpenDocument, RTF, WordPerfect, HWP), e-books (EPUB, MOBI, FB2), email (`.eml`, `.mbox`, `.msg`), archives (ZIP, TAR, 7Z, GZ, BZ2, XZ), SQLite, dBASE, CSV |
| `pagesift-syntax` | `yolowsyntax 0.1.2` | Tree-sitter / rule-based syntax highlighting and lossless tokenization across 373 languages (540 extensions, 64 filenames) |
| `pagesift-compress` | `yolowzstd 0.1.2` | Zstandard compression and decompression for HTTP payloads and `pagesift-store` cache records |

## PageSift DataGraph (`pagesift-graph`)

When enabled (`"graph"` format or `--graph`), PageSift builds relational structure and provenance alongside extracted content without requiring an external graph database:

- **Document citations:** cross-document link and reference edges between fetched/parsed sources.
- **Provenance lineage:** HTTP redirect chains, `<link rel="canonical">` alias clusters, and parent-document attachment relationships.
- **Version lineage:** temporal version edges connecting repeated fetches/crawls of the same logical document (`pagesift-store` snapshots).
- **Field-level evidence spans:** byte/block evidence mapping extracted structured fields and claims back to content blocks (`pagesift-extract` + `pagesift-graph`).
- **Cross-source fact clustering & conflict records:** grouping claims by subject keys and recording conflicting values across sources or versions.

### Interfaces

- **CLI**
  - `pagesift scrape --graph [--subject-keys ...] <url-or-file>`
  - `pagesift crawl --graph [--subject-keys ...] [--out DIR] <url>` — writes `graph.jsonl` and `graph_summary.json` into `--out`
  - `pagesift graph inspect <path> [--url ...] [--subject ...] [--json]`
- **HTTP API (Firecrawl v2)**
  - Include `"graph"` in `formats` or pass `graph: true | { enabled, citations, provenance, versions, evidence, claims, conflicts, canonical, subjectKeys }`
  - `GET /v2/crawl/{id}/graph` — inspect graph nodes, edges, clusters, and conflicts for a crawl job
  - `GET /v2/graph/history?url=...` — query stored cross-version history for a URL
  - `GET /v2/graph/conflicts[?subject=...]` — inspect recorded cross-source or cross-version conflicts
- **MCP**
  - Tool `pagesift_graph_query` (`jobId`, `historyUrl`, `conflicts`, `subject`)
  - `graph` option and graph output slices on `pagesift_scrape` and `pagesift_crawl`
- **Python & Node.js**
  - Python: `Format` includes `"graph"`, `ScrapeOptions(..., graph=True | {...})`, `Document.graph`
  - Node.js / TypeScript: `Format` includes `'graph'`, `graph` options, `Page.graph`, `PageJSON.graph`, `CrawlStream.graph`, `PageMetadata.canonicalUrl`

## Measured Performance (`1.4.0`)

Measured on `2026-11-14` on Linux `7.0.0-43-generic`, `Intel(R) Core(TM) i7-10700 CPU @ 2.90GHz`, 15 GiB RAM, `NVIDIA GeForce GTX 1070` (driver `580.178.04`), `rustc 1.99.0`, using the non-PGO unstripped release binary (`49.41 MB`, `51,813,752` bytes). OS page cache was warmed before `v2speed` and `b3b5`.

Only PageSift `1.4.0` was re-measured on available local offline corpora; `1.0` results remain carried forward for deleted offline corpora or live-web suites (`a1`, `a2`, `a4`, `b2`, `extract`, `dates`, `rag`, `crawl`, `wild`, `a3`, `browser`, `a2fast`), and competitor baselines (`xberg 1.3.9` from `2026-11-04` and historical runs from `2026-10-21/22/27/28`) were not re-run. See [benchmark history README](../../benchmarks/history/1.4/README.md) and [full report](../../benchmarks/history/1.4/results/final/new/report.md).

## Known Limits & Measurement Skips

- `firecrawl-py` official SDK compatibility test was skipped (`official_sdk_compatible: false`) because `firecrawl-py` was not installed in the local benchmark environment.
- `10M`-scale DataGraph stress benchmark was skipped in the `1.4` verification run (`1,000`-doc streaming and 2-version crawl E2E ran cleanly).
- Non-browser peak memory across `1.4` benchmarks ranged from `16.7 MB` (`v2.a2.cli.16w`) to `394.6 MB` (`v2.a2crawl.serve.1w`, with `a2` carried forward from `1.0`).
