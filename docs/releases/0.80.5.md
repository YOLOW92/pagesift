# PageSift 0.80.5 Release Notes: Honest Warnings, Bounded Documents, Patient Rendering

> **Release Version**: `v0.80.5`
> **Release Date**: 2026-10-28
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

Two more rounds of outside testing on 0.80.3 found places where pagesift returned a result that
looked fine but was not: an age gate returned as a 547-character "page" with exit code 0, data-loss
warnings that a Firecrawl client never sees, a 408 KB Word file that expanded into 84 MB of
Markdown, a damaged PDF whose missing pages went unmentioned, and a page rendered as its
"loading…" shell. 0.80.5 fixes each of them with a general rule rather than a special case, and
keeps the instruction counts of every benchmark within 2% of 0.80.0.

There was no 0.80.4 release: everything since 0.80.3 is in this one.

**Behaviour changes to know about when upgrading:**

- `data.warning` (and the response's top-level `warning`) is now filled whenever the result may be
  incomplete or wrong. Clients that treated any `warning` as an error will see more of them.
- Age gates and block pages that 0.80.3 returned as content now fail with `ACCESS_BARRIER`
  (kind `interstitial` or `block`), exit code 1 on the CLI.
- A body that is plainly HTML is treated as a web page even when it is labelled `application/pdf`.
- Word, Excel, PowerPoint, CSV and EPUB output stops at 16 MB of text with `output_truncated`.
- Misspelled values for `--engine`, `--format`, `--sitemap` and `tune --profile` are errors.

## Warnings a pipeline can see

Every warning has always been listed in `metadata.pagesift.warnings`, but Firecrawl's own
`data.warning` field was never filled, so a pipeline written against the Firecrawl format saw
nothing when a PDF lost a page of text. `pagesift::notice` now keeps one list of the warnings that
mean the result may be incomplete or wrong (`content_missing`, `pages_missing`, `fonts_missing`,
`thin_content`, `partial_content`, `empty_content`, `output_truncated`, `max_pages`, scanned PDF,
decoding errors, HTTP error status, `render_incomplete`, skipped rendering …). The common exit of
scrape, crawl pages and `/v2/parse` writes them into `data.warning`; the CLI prints the same list to
stderr, so the two can no longer disagree. `pdf_repaired` on its own is not on the list: a file whose
index was rebuilt but whose content is intact is not a data risk, and when content is lost a
specific warning says so.

Crawl output carries the same signal: `index.jsonl` rows and crawl JSON lines have `warning` when
the page has a data risk, and `crawl --out` now writes `summary.json` (`stopReason`, `coverage` with
`--adaptive`, `termEvidence`, `pages`) instead of leaving the stop reason on stderr only.

## Barriers

- **Age gates inside a large site frame.** The age-gate phrases were already in the barrier rules,
  but they only count when the whole page has little visible text; Steam's menus and footer bring
  its `/agecheck/` page to about 2,300 characters, so the check was skipped and the 476-character
  form came back as content. When the extracted main content is short (800 characters at most),
  made of short lines (no block over 150 characters) and holds a barrier phrase, the page is now
  classified on the main content alone. A short news item that mentions age checks is prose, not a
  form, and is not affected. ELDEN RING and The Witcher 3 return `ACCESS_BARRIER`; Counter-Strike 2,
  Jack Daniel's, Heineken and BBC News pages are unchanged. Age-gate phrases were added in German,
  French, Spanish, Chinese, Japanese and Korean.
- **Block pages labelled as PDF.** CDNs and WAFs sometimes send their HTML block page with the
  `Content-Type` of the file that was asked for. A body that starts like HTML is now handled as a
  web page whatever its label, so barrier detection applies (0.80.3 failed with "malformed PDF").
  A body that starts with `%PDF-` is still a PDF whatever its label.

## Bounded documents

HTML has always been limited by the response size limit (15 MB, also after decompression) and PDF
by its page limit. Word, Excel, PowerPoint, CSV and EPUB had no limit on what they produce: a
408 KB DOCX whose `document.xml` unpacks to 120 MB of repeated paragraphs gave 84 MB of Markdown
with a 348 MB peak and no warning. A single budget now covers all five formats, kept in the places
they share rather than in each converter: the XML reader counts the text it yields (DOCX, XLSX,
PPTX), CSV counts rows, EPUB counts chapters. Past `Limits::max_output_bytes` (16 MB) the XML reader
reports the end of the document and CSV and EPUB stop, so every converter finishes normally with what
it has and an `output_truncated` warning. The same DOCX now gives 17 MB, peaks at 171 MB (the rest is
the unpacked XML, bounded by the existing per-entry zip limit) and says so. An EPUB spine that lists
the same chapter many times converts it once.

## PDF damage warnings

- `content_missing` and `fonts_missing` count against the document's page count, not the pages
  that were recovered, so the denominator no longer shrinks as the damage grows.
- A page that lost only some of its content streams says so: `pages 1 (1 of 2 streams)`. arXiv adds
  its side watermark as a second content stream at the end of the file; cutting the tail loses only
  the watermark, which 0.80.3 reported as the whole page.
- When the page tree is lost and nothing left in the file states the page count, `pages_missing`
  says the total is unknown and later pages may be missing. A 15-page paper cut to 15% came back as
  13 pages with no word about the other two.

## Rendering

- **Pages that fill in after a timer.** Rendering counted a page as ready once the network had been
  quiet for 100 ms. A page that writes its content from a timer, without a request, was captured as
  its "loading…" shell on every engine (moli only looked better because of incidental requests that
  kept the network busy). When the network is quiet but the page has almost no text (under 200
  characters), rendering now looks again every 250 ms for up to 1.5 s and stops as soon as text
  appears. Pages that already have text pay one extra text-length check.
- **No silent shells.** When one engine renders only a shell and the engines after it fail, the
  shell is returned with `render_incomplete`, naming the engines that failed.
- **Virtual scroll** waits for each step's own `scroll` event before collecting. On a slow machine
  it used to read the old rows while later scrolls merged into one event, losing whole screens
  (100 rows came back as 90 on CI). `behavior: instant` also stops pages with smooth scrolling from
  waiting out the animation (3.0 s → 0.8 s on a 100-row list).

## Command line

`--engine`, `--format`, `--sitemap` and `tune --profile` list their allowed values; anything else
is an error. `--engine potato` used to run as `auto` without a word.

## Tests and CI

The macOS CI had failed six times in a row, each time on a different test, always for the same
reason: a test that waited a fixed time or judged speed by the wall clock on a busy runner. The
complexity guards now measure the CPU time of the calling thread (the unpublished
`pagesift-testkit` crate), the per-origin connection controller keeps one clock and its tests run
on a paused clock, and the wall-clock bounds that remain sit just under the time the bug would
take. Under a fully loaded CPU the old PDF stress test failed 5 of 5 runs and the new one passed
5 of 5. `scripts/check_release.py` also checks that `SECURITY.md` names the current release line
(it still listed 0.20.x).

before and after these changes).

## Looked into, not changed

- **HTTP gzip.** Decompression was already capped by the response size limit, with a warning: a
  100 MB gzip bomb gives 15.6 MB and a 68 MB peak.
- **A 30 MB CSV field.** Output is the size of the input, not an amplification; over HTTP it is cut
  by the response size limit, and uploads now fall under the output budget. The budget cuts CSV by
  row, so a single oversized row is dropped whole, while Word cuts by paragraph.
- **No title for a damaged PDF.** When page 1's content stream is gone, the title text is gone with
  it; the inferred title has nothing to read.
- **`coverage` in `index.jsonl` and `crawl -o`.** Neither ever existed; coverage now has
  `summary.json`, and the output directory is `--out`.
- **Fake-IP proxies.** Behind a proxy whose DNS answers every name with an address in
  198.18.0.0/15, pagesift's private-network guard refuses the target (`SSRF_BLOCKED`). This is the
  guard working as designed; allow the range with `--allow-cidr 198.18.0.0/15` on such networks.
