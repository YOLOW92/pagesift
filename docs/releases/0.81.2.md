# PageSift 0.81.2 Release Notes: Zero Content Loss for Adaptive Upgrades

> **Release Version**: `v0.81.2`
> **Release Date**: 2026-10-30
> **License**: AGPL-3.0-only (Commercial licensing available)

---

## Overview

0.81.1 stopped `engine: auto` browser upgrades when the extracted content stopped improving. That
removed the tail latency of JavaScript shells and challenge pages, but one class of page lost
content: a page whose HTTP body is a bare client-side redirect and whose target only becomes
readable after its scripts run. The browser was stopped before the target content appeared, so the
HTTP result (empty) was returned.

0.81.2 keeps the adaptive stop and adds a content-first path for those redirect pages:

- **Content appears, capture immediately.** For a bare redirect page, the browser is polled for
  the first non-empty main frame; the DOM is captured and extracted as soon as content appears,
  without waiting for `DOMContentLoaded` or network idle.
- **Relative patience.** The wait is bounded by the page's own HTTP fetch time and the caller's
  total timeout, not by a fixed number of seconds. If no content appears, the HTTP result is
  returned as before.
- **No change for normal pages.** The adaptive probe, early stop and HTTP fallback from 0.81.1 are
  unchanged. Explicit `engine: browser` is still uncapped.

## Measurements

Local A2 replay, 269 pages, same per-URL process model as the 0.81 report:

| Version | 1 worker | 16 workers | Extracted characters |
|---|---:|---:|---:|
| 0.81.0 | 110.7 s / 2.4 pages/s | 21.9 s / 12.3 pages/s | 2,376,184 |
| 0.81.2 | **88.0 s / 3.1 pages/s** | **13.5 s / 20.0 pages/s** | **2,376,358** |

Per-page comparison against 0.81.0: **zero pages lose content**. The redirect page that motivated
this release returns 476 characters instead of 405, and its wall time falls from 17.0 s to 9.4 s.
The total is +174 characters.

0.81.1 was faster on this replay (85.7 s / 10.5 s) but returned 301 fewer characters overall
because it dropped that redirect page's content. 0.81.2 deliberately spends a few seconds on that
page to keep the zero-loss guarantee; it remains 1.26× faster than 0.81.0 at one worker and 1.62×
faster at 16 workers.

## Behaviour changes

- A bare client-side redirect with no HTTP content now waits for its target's first content and
  captures it immediately. If the target never produces content, the HTTP result is returned with
  the same fallback warnings as 0.81.1.
- No configuration or API changes.
