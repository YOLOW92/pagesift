# 六项目对比调研与改进方案

日期：2026-10-22（Asia/Tokyo）。本阶段为源码、开发历史与文档抽查，未运行六个对手的基准测试，以下不构成性能排名。首轮调研的 pagesift 快照为 `096407408603bb82ef0eba52b22758b0c7ea19e8`；执行实验时重新冻结实际 SHA，不能复用这个值冒充最新版本。

## 0. 按既有开发流程重订方案

本次方案以提交历史、实际脚本和原始结果为依据。PRD 表示目标，不能代替已经执行的证据；例如 PRD 中仍有旧依赖和发布门槛描述，而代码早已替换相关依赖。以下数字来自历史提交或报告，本轮没有独立重跑。

### 既有流程需要保留与补强的细节

- **延续三层评测。** 提取 CPU、单页端到端、大规模吞吐/内存分开；专项质量、稳定性与功能覆盖另列。
- **保留开发期核池。** `pinned.sh` 可用于不同物理核上的探索任务，已有内存并发限制和底层线程池限制。绑核不能隔离内存带宽、缓存和功耗，最终计时仍逐工具独占机器；吞吐与浏览器整树内存测试始终独占。
- **改前改后同场对照。** 每轮保留可执行的旧二进制/构建信息，在相同输入上比较 baseline、candidate 和对手；实时站点交替运行顺序，避免后运行者总受限流影响。
- **延续评分器校准。** 历史上修过空白归一化、truth/noise 重叠和短噪声误命中。新修正先用人工可解释样例验证，提升评分器版本，再重算所有工具；不能只重算 pagesift，也不能把评分变化算成引擎改进。
- **兼容测试已有起点。** `tests/compat/firecrawl_sdk.py` 已覆盖 Python SDK 的 scrape、links、metadata extras、部分错误和 batch 轮询。此次扩展到 JS、crawl/map、分页/取消和固定本地场景，不能写成从零建立兼容性验证。当前 `scripts/ci.sh` 没有直接调用此脚本或全量质量评测，接线与是否执行要明确。
- **续跑需要更强校验。** `run_extract.sh` 主要凭结果行数和进程名称判断完成；本次必须核对输入哈希、工具/适配器版本、参数、样本 ID 唯一性与退出状态，防止旧结果混入新版本。
- **保留最终独立验收。** 既有 tune/hold 适合开发验证，反复查看过的 hold 不再称为完全未见数据；最终单独冻结站点家族和快照，开启前锁定候选。验收后若继续调优，该集合转为验证集。

## 2. 源码发现与 pagesift 的对应机会

### Firecrawl：优先验证兼容性与端到端结果

- 当前版本包含 Rust 原生 HTML 处理模块，不能将对比简化为 Rust 对 TypeScript。
- 自托管基线使用 Playwright 和 fetch 回退；可选外部引擎、模型供应商必须单独标注。源码自托管结果不能代表托管产品结果。
- 把相同版本的官方 Python/Node SDK 指向 pagesift 与 Firecrawl，验证 scrape、batch、crawl、map、状态轮询、分页、取消、错误和输出格式。超出 pagesift 支持范围的 API 明确列出。
- 内容评测使用同一份静态输入；端到端评测单列部署、浏览器、外部服务及缓存成本。
- 不以“把对方核心代码翻译为 Rust”作为本项目默认实现路线；按 pagesift 的第三方代码政策记录来源并选取可接受的实现。

依据：[自托管基线](https://github.com/firecrawl/firecrawl/blob/253ee3f62495c7ef64b3890cecda3e9e8c295c7c/SELF_HOST.md)、[Rust HTML 模块](https://github.com/firecrawl/firecrawl/blob/253ee3f62495c7ef64b3890cecda3e9e8c295c7c/apps/api/native/src/html.rs)。

### Crawlee：最值得优先做差距实验的对象

- 渲染预测按 request label 和 URL 相似度学习；冷启动和低置信度时增加双模式探测。可比较 HTTP/浏览器结果，失败尝试的存储写入可回滚。
- 资源调度考虑内存、CPU、事件循环、存储后端负载；Rust 实现应使用适合 Tokio 和存储层的信号，不机械照搬 Node 指标。
- pagesift 的 `src/learn.rs` 按 host 累计渲染收益，按字符增量判断是否值得渲染；同站页面类型混合是应验证的潜在弱点，尚未实测证明。
- 候选实现：按 origin + 路径模板分组，加入内容/必需字段完整性判断、低置信度探测、失效与重新学习。路径分组限制数量，记录探测成本，避免扩大无界状态。
- 先验证简单分组方案，不默认移植其逻辑回归模型；收益足够时保留较简单的 Rust 方案。

依据：[渲染预测源码](https://github.com/apify/crawlee/blob/94abff8c1a1c6c9ab5c18b06895a307b35ef0e2d/packages/playwright-crawler/src/internals/utils/rendering-type-prediction.ts)、[自适应流程](https://github.com/apify/crawlee/blob/94abff8c1a1c6c9ab5c18b06895a307b35ef0e2d/docs/guides/adaptive-crawling/adaptive-crawling.mdx)、[并发控制](https://github.com/apify/crawlee/blob/94abff8c1a1c6c9ab5c18b06895a307b35ef0e2d/packages/basic-crawler/src/internals/autoscaling/concurrency-system.ts)。本地对应：`crates/pagesift/src/learn.rs`、`crates/pagesift-cdp/src/pool.rs`。

### Scrapling：结构化抽取的抗改版能力

- `relocate` 遍历候选 DOM 节点，比较标签、文本、属性、路径、父节点和兄弟节点，返回达到阈值的最高分候选；这属于启发式相似度，不是校准后的正确概率。
- pagesift 已有 CSS/XPath 结构化抽取，应先测精确查询、字段覆盖和失败行为，再决定是否增加元素特征持久化与重新定位。
- 数据包含真实改版前后快照，以及可解释的结构变换：改 class/id、增加包装层、重排列表、改变文本、删除目标、添加相似干扰节点。
- 主要指标是字段正确率、错误匹配率、拒绝匹配率；“总能找到一个节点”不能算成功。
- Rust 候选实现可先做候选筛选，再做特征评分，并要求首选与次选之间有足够差距；上述设计须在独立样本验证。

依据：[parser.py：relocate 与 similarity](https://github.com/D4Vinci/Scrapling/blob/8a340fe207cd2f4e85fbd99a9ac86478075d3937/scrapling/parser.py)、[自适应功能说明](https://github.com/D4Vinci/Scrapling/blob/8a340fe207cd2f4e85fbd99a9ac86478075d3937/docs/parsing/adaptive.md)。本地对应：`crates/pagesift-extract/src/`。

### Katana：发现率必须与有效内容覆盖率一起测

- 发现源覆盖 HTTP 头、多个 HTML 属性、HTMX 属性；可选 JavaScript 正则/解析器提取。安全爬虫发现的资源不一定是 RAG 应抓取的内容页。
- pagesift 的公开内容链接提取函数主要处理 `a[href]`、`area[href]`；爬取层另有 sitemap 等来源，不能只依据这个函数断言全部发现能力。
- 建立已知 URL 图，包含普通链接、HTTP Link、Refresh、iframe、JS 中的内容路由、无效字符串、资源 URL、越界链接及重复路由。
- 分别报告所有端点召回、内容页召回、发现精度、实际访问覆盖、无效请求占比、越界请求和请求预算。
- 候选改进：增加带来源标记的发现候选，再通过内容类型、作用域、礼貌策略和请求预算筛选；不把所有资源都自动入队。

依据：[响应解析器注册](https://github.com/projectdiscovery/katana/blob/ebaa3cad5376d24500a4a7749475ae7f30ea378a/pkg/engine/parser/parser.go)、[JS 发现](https://github.com/projectdiscovery/katana/blob/ebaa3cad5376d24500a4a7749475ae7f30ea378a/pkg/engine/parser/parser_generic.go)、[路径指纹](https://github.com/projectdiscovery/katana/blob/ebaa3cad5376d24500a4a7749475ae7f30ea378a/pkg/utils/urlfingerprint.go)。本地对应：`crates/pagesift-content/src/links.rs`、`crates/pagesift/src/frontier.rs`、`crates/pagesift/src/crawl.rs`。

### Essence：优先加入固定输入的正文与 Markdown 对比

- 同为 Rust HTTP + Chromium 回退路线，产品定位接近；还提供 CSS/LLM 抽取、分页检测和 SSE crawl。
- Markdown 管线包含 html2md、HTML 预处理、图片处理、布局表格清理和转换后修正。需要测深层 DOM、合法复杂表格、代码和图片，而不是仅测输出长度。
- README 的质量胜率来自其自己的 35 URL、LLM 裁判实验，不能当成已被独立复现的广泛优势。
- 复用现有固定 HTML 适配器协议，比较正文召回/噪声、Markdown 结构保真、延迟、内存、崩溃与超时；LLM 盲评仅为补充。
- 它已是 Rust，改进重点应是失败样本中的具体规则或算法，不是语言转换。

依据：[README 与评测范围](https://github.com/ruchit-p/essence/blob/74a99fb64b9c6c65846c6e4ecc6f177b1b0bc66b/README.md)、[Markdown 管线](https://github.com/ruchit-p/essence/blob/74a99fb64b9c6c65846c6e4ecc6f177b1b0bc66b/backend/src/format/markdown.rs)、[分页检测](https://github.com/ruchit-p/essence/blob/74a99fb64b9c6c65846c6e4ecc6f177b1b0bc66b/backend/src/crawler/pagination.rs)。

### gallery-dl：借鉴增量采集设计，暂不扩成媒体下载器

- 核心是站点专用 extractor、请求与分页规则、媒体条目元数据和下载归档，不是通用正文转 Markdown。
- 归档层支持稳定键与 SQLite/PostgreSQL 去重；值得验证 pagesift 重复采集时的重复输出、内容更新和断点行为。
- 媒体文件、站点 API 和完整图集不是 pagesift 当前同等能力，不纳入 Markdown 或吞吐排名。
- 使用本地受控分页 API 重放对比适配器的增量语义；端到端站点对比只选双方真正支持的任务。必要时仅将 gallery-dl 作为独立参考程序。
- 根据当前第三方代码政策，不直接翻译或引入其 GPL 源码；候选 Rust 功能以独立需求、输入输出和测试定义。该选择是实施约束，不是法律结论。

依据：[项目说明](https://codeberg.org/mikf/gallery-dl/src/commit/5b0d6c8c3b416eb0e1e89a7fbc96c7b018d92a94/README.rst)、[Extractor 基类](https://codeberg.org/mikf/gallery-dl/src/commit/5b0d6c8c3b416eb0e1e89a7fbc96c7b018d92a94/gallery_dl/extractor/common.py)、[归档实现](https://codeberg.org/mikf/gallery-dl/src/commit/5b0d6c8c3b416eb0e1e89a7fbc96c7b018d92a94/gallery_dl/archive.py)。

## 3. 公平性与证据要求

1. **固定输入与完整抓取分开。** 固定原始 HTML 和独立生成的渲染快照；禁止由 pagesift 当前的内容长度阈值决定所有工具的输入。实时抓取另列网络、访问屏障和浏览器失败。
2. **开发、验证、最终验收分开。** 按站点/模板家族划分，防止同站近重复跨集合泄漏。反复参与方案选择的旧 hold-out 降为验证集；最终验收集不参与调优。样本不足时如实标注探索性结果。
3. **默认与同等预算分开。** 展示开箱默认配置，以及统一并发、请求数、期限、浏览器和礼貌规则下的配置；公布适配器代码和差异。安全防护测试独立运行，不为吞吐放开实际公网内网边界。
4. **失败不得消失。** 所有工具对同一输入清单返回结构化结果，包括失败、空输出、超时和被策略拒绝。质量对共同成功样本与全部样本分别统计，并解释分母。
5. **性能不能牺牲内容完整性。** 在质量可接受时比较时间和内存；报告每工具完整进程树的 PSS、CPU 时间、冷/热缓存和 p50/p95。探索期允许物理核隔离并记录条件；最终性能测试串行，多轮重复，记录原始测量与波动。多服务部署计入全部服务和浏览器的资源，不能只测 API 启动进程的后代。
6. **结果具备不确定性。** 内容指标报告逐站点分布和按站点重采样的区间，避免把同站页面当独立证据。极小差距标为无确定结论。
7. **托管成本可见。** 托管 Firecrawl 单独成轨，记录服务时间、计费单位、外部模型/服务和网络条件；没有实际访问和运行就标记未测。
8. **代码来源可追踪。** 每次移植记录来源 SHA/文件、许可证、保留声明、依赖及修改说明，按文件核查。不能声称换语言后代码来源约束消失。
9. **结论可审查。** 保留输入哈希、样本划分、版本清单、运行日志、原始输出、逐样本得分、失败案例和生成报告的命令。公开数据受限时提供获取与校验脚本，并标注限制。

## 4. 本轮执行流程

### 阶段 A：六家一起盘点、冒烟与冻结基线

先产出六份源码与功能对照记录，不能只挑预期容易赢的项目开跑。每项能力记录：入口、默认参数、源码/测试路径、外部依赖、是否已在 pagesift 实现、是否可比、是否属于刻意不做的功能。

- 保留 pagesift 当前发布构建与全部配置；检查旧回归线和现有 CI 状态，记录阻碍。CI/发布修复不阻止隔离环境中的源码调研与适配器开发。
- 对手优先选可安装的稳定发行版，同时记录本次默认分支快照；如稳定版与默认分支有关键能力差异，单独建实验轨道，不混成一个版本。
- 每家先跑约 10–20 个适合其能力的冒烟用例，检查正常、空结果、失败、超时、Unicode、重复和持久化行为。这是适配器校验，不用于宣传排名。
- 固定数据与评分器后，全量跑出“未改进 pagesift”基线；已有 Crawl4AI/crw/Spider 等结果不能直接与新版本新输入混表。核心旧对手在共同任务上保留作锚点，非相关领域不强迫全跑。

### 阶段 B：按任务建立四条可复用实验轨道

| 轨道 | 主要对比对象 | 数据和已有设施 | 新增能力与输出 |
|---|---|---|---|
| 内容质量与转换 | Firecrawl、Essence；Scrapling 只测它实际提供的输出能力 | Firecrawl 标注集、AEB、随机站点、Markdown 往返、编码；复用 `bench/compare`、`bench/markdown`、`bench/fresh` | 原始/渲染快照分轨；正文/噪声、表格代码公式、字符编码与错误；若只能测完整服务就单列端到端，不伪装离线组件 |
| 抓取、渲染、调度与发现 | Crawlee、Katana、Firecrawl、Essence；Scrapling 按实际 crawler/fetcher 入口纳入 | 复用 `origin`、`wild`、`measure.py`、`real_sites.py` 与浏览器内核场景 | 同站静态/动态混合、429/503、长尾页、JS 路由、作用域与资源压力；发现图、合格交付、CPU/PSS 和请求日志 |
| 结构化抽取与改版 | Scrapling、Essence、Firecrawl 对应能力 | pagesift CSS/XPath schema 测试、真实快照 | 固定字段金标、前后版本 DOM、目标删除/干扰负例、LLM 与非 LLM 独立；字段正确率、错误匹配、拒绝率、耗时 |
| 增量、恢复与条目身份 | gallery-dl、Crawlee，其他工具按实际能力加入 | pagesift store/API 恢复测试与本地重放源站 | 重复运行、翻页变化、新增/修改/删除、处理中断重启；条目遗漏、重复、重抓、持久化成本及恢复时间 |

**对比边界必须落实到适配器：**

- Crawlee/Katana 等工具若只负责抓取/发现，先统一判定抓到的 HTML、字段或 URL 图；不强制给它们接入劣质 Markdown 转换器，也不把额外转换器的耗时当成原工具固有成本。确需端到端组合时公开组合和费用。
- Katana 的“所有可发现端点”和 pagesift 的“适合 RAG 的内容页”是两套金标，分别报告。相同范围/方法的 GET 抓取作为共同轨道，原生更多发现能力另列。
- Scrapling 的 parser 微基准、选择器重定位和完整爬取分开；不能用纯解析器耗时对比 pagesift 完整网络请求。
- gallery-dl 首先选它已有 extractor 支持的少量公开内容站点，记录分页响应与条目金标，保留其真实解析逻辑重放；凭证不写入产物。pagesift 缺失媒体/站点适配时明确列为能力缺口，不计作现有正文能力失败。
- 通用合成分页服务可用于 pagesift 的增量设计验证；若给 gallery-dl 另写测试 extractor，必须标记为自定义适配实验，不能作为原生站点覆盖率证据。站点 API、图片元数据与正文分别评分。
- LLM 抽取仅在同一模型、提示词、schema、预算和重试条件下对比，原生默认提示另列；记录 token 和成本。没有服务配置时如实标为未测，不替代为假结果。

### 阶段 C：生成差距清单，再决定改什么

沿用 `bench/pdf/diff.py` 与历史正文诊断的思路，为每条实验轨道生成逐样本差分，至少包含：样本 ID、金标、双方原始输出、失败类别、差距大小、复现命令、候选源码位置。

按照“对手成功而 pagesift 失败”“两者成功但字段/正文错误”“质量相近而成本高”“pagesift 独有退化”分组。按用户影响、出现频率、可迁移性和实现成本排序；在全六家基线之后决定实施优先级，不预设 Crawlee 一定存在已证实的领先。

每个优先问题形成一个独立工作单：

1. 最小复现与未改版本结果。
2. 对手为什么成功：具体函数/算法/测试，或外部服务与配置差异。
3. 选择路线：修本项目 bug、重实现参考算法、自研替代、仅补 API/适配，或记录范围外能力。
4. 改前冻结本问题的验收条件、质量容差、资源预算及不允许退化的旧任务。
5. Rust 修改、来源记录、回归样例、消融结果与独立验证。无有效收益的方案保留实验记录，不合入产品。

### 阶段 D：照既有做法完成 Rust 改进，而非停在排行榜

| 对象 | 差距确认后可执行的工作方向 | 等价/改进的验证方式 |
|---|---|---|
| Firecrawl | API/错误/任务状态适配，内容清理与格式缺口的自研实现 | 扩展现有官方 Python SDK 检查，加 JS；固定源码服务与 SDK 版本；契约和内容分开验收 |
| Crawlee | 页面类型渲染学习、资源反馈、任务确认/恢复语义 | 同路径族混合页、冷启动与改版、崩溃注入；内容完整性与无效渲染同时衡量 |
| Scrapling | 精确字段查询缺陷修复；需要时增加 Rust 元素特征与重定位 | 先以参考实现做差分，再用有金标的独立改版样本；负例必须能拒绝 |
| Katana | 缺失发现源、URL 候选 provenance、范围过滤 | 固定发现图与原生测试样例，比较找回/误入的具体 URL；不破坏礼貌和内容预算 |
| Essence | 正文、Markdown、分页等具体规则缺口 | 同 HTML/DOM/字段/页图逐例对比；若采用其 Rust 代码/算法，同样记录来源与保留声明 |
| gallery-dl | 自研稳定条目身份、分页断点与增量去重；必要的站点适配 | 已支持站点重放 + 通用故障测试；明确 URL 身份、条目身份和内容版本的区别 |

参考算法移植先以相同行为为目标，再把可测的优化放到下一步；自研方案不用追求和对方每个行为一致，但要满足独立金标。继续沿用 `NOTICE` 的来源记录，并按具体文件处理许可要求；外部测试工具与产品依赖分开。

每轮至少比较 `pagesift-baseline`、`pagesift-candidate`、本任务对手三者；旧基线和候选共享相同输入与评分器版本。运行相关领域全量质量与性能检查，再运行 `scripts/ci.sh`；专项 SDK/质量基准要显式调用，不能因 CI 绿灯就声称已覆盖。算法不相关的低影响修改不强迫重跑所有昂贵领域，最终验收再全量运行。

### 阶段 E：独立验收与公开结果

- 锁定候选 SHA，干净克隆构建；锁定对手版本与全部依赖。新主种子、新站点家族/快照；这是独立样本验证，不是第三方独立审计。
- 所有计时任务按工具独占机器运行，HTTP、浏览器、多服务分别计账。性能建议每配置至少五次测量，记录预热、顺序、波动与异常；高成本轨道不足五次时披露，不用单次结果宣称小幅领先。
- 全量覆盖已运行的六家相关轨道，并复跑旧正文/日期/Markdown/RAG/PDF/爬取回归。明确哪些旧领域未增加新对手，只承担回归作用。
- 新语料若暴露问题，进入下一轮开发并降级该验收集的独立性；修复后另取最终验收样本。不得反复调参仍宣称完全未见。
- 报告分别列“对手 → 改进前 pagesift → 改进后 pagesift”、逐领域得失和未支持能力。阈值依据任务制定，旧 PRD 对 Crawl4AI 的倍数目标不直接套给所有六家。
- 发布表格从同一批结果生成，并标指标方向、版本、样本数、缓存与配置、计时边界。小差距或样本不足时报告无确定结论；没有达成优势就如实写。

## 5. 实验产物与现有脚本复用

下列为待实施目录约定，不表示 runner、adapter 或结果已经存在。保留现有专项脚本，在它们外层补统一编排与校验，不重写已有效的评分器。

```text
bench/six/
  README.md                 # 从准备到复测的步骤、环境和能力边界
  tools.lock.json           # 工具、SHA/tag、锁文件/镜像摘要、浏览器、模型配置
  capabilities.json         # 六家功能/入口/适用轨道/缺口矩阵
  adapters/                 # 薄适配器；不偷偷补齐或削弱对手算法
  fixtures/                 # 小型可分发、可人工校验的冒烟和反例
  prepare.py                # 数据获取、哈希、分组划分、独立快照
  run.py                    # 资源隔离、期限、状态、续跑与原始输出
  score.py                  # 调用旧评分器 + 新任务评分，保留版本
  diff.py                   # 逐样本差距、诊断位置和最小复现
  report.py                 # 由同批结果生成表格，拒绝缺结果的伪成功
  results/<run-id>/          # manifest、配置、运行状态、scores、diff、报告
```

原始数据与大输出按既有 `bench/data/` 约定存储；结果目录保留校验清单与获取方法，敏感或不可再分发材料不直接提交。每条结果至少记录 `run_id`、tool/build、config hash、adapter/scorer hash、sample ID/input hash、status、输出位置、wall/CPU 和内存测量边界；工具返回错误与实验基础设施故障分开标识。

续跑仅复用全部身份与哈希一致、样本完整且退出状态已记录的任务。基础设施失败阻止出具完整排名；工具本身失败仍保留在结果分母。对 JSONL 行数相同但 ID 缺失/重复、版本变动、输出截断等情况一律不当作完成。

## 6. 第一批交付与停止条件

第一批交付是六家的能力/版本矩阵、冒烟适配校验、未改 pagesift 的相关轨道基线和按影响排序的差距清单。随后每个选中的差距交付一组“复现 + Rust 修改 + 来源 + 三方复测 + 旧领域回归”证据；最后交付干净克隆的验收报告。这样保持之前评测驱动开发的节奏，同时让第三方能够复查。

不以“六家全部指标都输给 pagesift”为完成条件，也不因做出漂亮总分就停止。每个约定任务以功能正确、证据完整、改进达到预先约定条件且无不可接受退化为验收；未测、范围外、无收益和仍落后的部分明确保留。当前文档未声称任何新适配器、算法或基准运行已完成。
