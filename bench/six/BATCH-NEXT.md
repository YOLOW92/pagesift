# 换批测试：WCXB 全部 511 页，冻结代码不调参

本次使用另一套 WCXB 上游 test 数据，**511 页全部纳入**，未与此前 AEB / Readability 正文输入发生 URL 或 HTML 字节哈希重复。当前版正文组件在这批数据上高于固定 Essence 组件；相对改进前版本仅略高，**不能认定新改动带来稳定的整体提升**。

## 固定输入、版本与口径

- [WCXB 上游源码](https://github.com/Murrough-Foley/web-content-extraction-benchmark/tree/c039d5ee9f5a3a984a0e167e63aacd04e76e78a9)，版本 `c039d5ee9f5a3a984a0e167e63aacd04e76e78a9`，test split，CC-BY-4.0。使用原始 HTML 快照及原始 main_content 金标，不抓取当前网页，不替换失败样本。
- 7 类页面：257 文章、51 论坛、28 商品、34 集合、40 列表、42 文档、59 服务。实际 URL 共有 **472 个有效主机名**，另 1 页缺少 URL；原始 manifest 把该缺失组也计入 domains，因此协议记录为 473 组，并非 473 个有效域名。
- 包含 4 个上游标记的 SPA，仍在分母内。本轮测试离线 HTML 正文转换，不运行浏览器；不能据此评价完整动态抓取、爬取恢复或媒体下载能力。
- 当前源码冻结为 `546b9e242d0b8f062845f5ad7ba7b02e4f3c12de`，改进前基线为上一轮保留的 a1d834ef 源码对应转换器；Essence 使用 tools.lock 固定 v0.3.0 源码模块的薄离线适配器。输入字节、URL、每页 10 秒上限、每工具 2 个工作进程相同。
- 主指标为**上游 evaluate.py 的逐页词级 F1 平均值**，不是前两轮 AEB 四词 shingle 指标，不能把本次 0.86 与上轮 0.93 直接相减。
- 三个转换器均输出 Markdown，再统一使用固定 aeb.py plain() 去格式。调用上游原评分函数，并额外通过原 evaluate.py CLI 核对结果。失败按空预测保留，未筛选有利页面。

冻结协议及二进制哈希 (local `results/batch-next/protocol.json`)、511 页清单及哈希 (local `results/batch-next/manifest.jsonl`)。

## 异常与可重复性

- 当前版与改进前均完成 **511/511**，无进程失败、无超时。Essence 完成输出 510 页，另有 4129 因**上游 URL 为空**返回 InvalidUrl。它在主分数中按预置规则计空预测，但这不等同于已证明其正文算法失败。
- 事后补充有效绝对 URL 的 510 页敏感性分析：当前 **0.86348508**、改进前 **0.86338017**、Essence **0.82450811**。主结果仍为全 511 页，未用该子集替换结果、未补抽样本。
- 当前有 4 页 F1=0：4066、4482、4542 的金标为空而预测非空；4145 论坛页金标非空但预测为空。它们均未剔除，需逐例复现后再决定是正文边界、拦截页处理还是快照/标注问题。
- 原始 HTML 均可正常 UTF-8 解码，无替换字符引入。输入与金标 SHA256 保留。
- 事后进行了**同版、同输入全量复跑**：511/511 Markdown 逐字节一致，重复 F1 仍为 0.86373821。复跑未替换主实验、未挑选最高分。复跑记录 (local `results/batch-next/replay/summary.json`)。

## 资源与交付

所有任务共享 8 个逻辑 CPU / 8GiB RAM、任务 swap 0 的 slice。三个主工具各限 2 CPU / 2GiB，最多两个工作进程，合计预算未超过全局上限。实际主工具服务峰值：改进前约 51.4MiB、当前约 51.2MiB、Essence 约 64.3MiB（包括各自驱动/子进程），没有依据混合构建类型的耗时作速度排名。
