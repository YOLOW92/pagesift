# PageSift 0.50 基准评测：D5 高性能 RAG 语义分块与 BM25 QueryFilter 全量对决报告

## 1. 评测背景与测试方法论

在大模型检索增强生成（RAG）流水线中，前置分块（Chunking）与上下文粗筛（QueryFilter / Pre-filtering）是决定后续 LLM 生成质量与 Token 成本的咽喉枢纽：
1. **分块质量 (Chunking Quality)**：分块过大导致检索引入大量无用噪音；分块过碎导致语义割裂。分块器需在保留 Markdown 结构层级（标题路径、表格、代码块）的同时，产出具有高检索区分度的文本块；
2. **分块吞吐与内存经济性**：企业级 RAG 往往需要对数千篇技术论文、财务年报或代码文档进行高吞吐切分，避免出现 $O(N^2)$ 递归正则回溯或内存溢出；
3. **前置语义过滤 (QueryFilter)**：直接将几十万字的长文档输入 LLM 成本高昂且命中率低。QueryFilter 在切分阶段基于 BM25 和拓扑邻域打分，剔除 90% 以上无关段落，仅保留核心高权重上下文。

### 硬件与评测环境
- **服务器配置**: Google Cloud Compute Engine
  - **CPU**: AMD EPYC 9B45（32 物理核心 / 32 线程，AVX-512）
  - **内存**: 128 GB DDR5 RAM
  - **看门狗保障**: 统一设定 **120 GB** 内存上限监控与全进程树实时追踪
- **并发调度（全面避免单线程）**:
  - **PageSift 0.50**：采用原生 Rust 多线程架构（`chunk_spans`、`qf_ranks`、`bench_qf_storm`），在 32 颗物理核心上全并发调度；
  - **Python 竞品阵营**：解除单核绑定，采用 32 进程分片并行运算。
- **评测数据集（官方学术与工业基准全量引入）**:
  1. **Dataset A: Chroma `chunking_evaluation` 官方基准集**：5 份多领域长文档（财务年报 `finance.md`、PubMed 论文 `pubmed.md`、维基百科 `wikitexts.md`、国情咨文 `state_of_the_union.md`、Slack 对话 `chatlogs.md`，1.4 MB），472 道由人工精准标注答案字符区间的黄金问题集；
  2. **Dataset B: AllenAI `QASPER` 官方全量学术基准集**：416 篇 NLP 领域全长科研论文，1,279 道基于段落事实证据严格标注的学术 QA 数据集；
- **参评竞品全家桶 (6 大框架、11 种策略同台竞技)**:
  1. **PageSift 0.50**（Rust）：`pagesift-recursive`、`pagesift-sliding`、`pagesift-fixed`、`pagesift-default (QueryFilter)`；
  2. **semchunk 3.2.5**（Python）：号称业界最快的纯 Python 语义分块器；
  3. **chonkie 1.7.0**（Python + Rust core）：`chonkie-recursive`、`chonkie-sentence`、`chonkie-token`；
  4. **LangChain Text Splitters 1.1.3**（Python）：工业界最为普遍的生产级分块基线 `RecursiveCharacterTextSplitter`；
  5. **LlamaIndex Core 0.14.25**（Python）：头部 RAG 框架官方分块引擎 `SentenceSplitter`；
  6. **Crawl4AI 0.9.5**（Python）：`crawl4ai-sliding`、`crawl4ai-fixed`、`crawl4ai-queryfilter (BM25ContentFilter)`。

## 5. 结论与工程实践建议

1. **RAG 质量与性能的黄金分割点**：在 Chroma 与 QASPER 双官方基准上，`pagesift-recursive` 实现了检索指标（Recall@1000: 0.893 与 0.175）第一，同时耗时仅为 LangChain 的 **1/8**、Semchunk 的 **1/5**、LlamaIndex 的 **1/62**；
2. **前置过滤带来数量级 Token 节省**：PageSift QueryFilter 具备 **40 微秒 ~ 0.63 毫秒** 的瞬时过滤性能，不仅较 Crawl4AI 提速 **1,330x ~ 2,185x**，更将输入大模型的文档词数压缩 **97.6%**（从 4.9 万词压缩至 1,157 词），同时保留 **92.9%** 的黄金答案；
3. **彻底杜绝极端语料下的定位崩溃**：Crawl4AI 等缺少原生区间偏移的方案在超大文本（50MB）下因二次定位导致 $O(N \cdot M)$ 算法崩溃，而 PageSift 的原生字节-字符映射表始终保持线性与微秒级处理。
